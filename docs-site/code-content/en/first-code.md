# Your first Code

You can build Code in two places. Both use the same tools and the same
contracts, so you can start in one and continue in the other.

- **In a Gustav chat:** describe what you need. Gustav creates the project,
  reads your SDK, writes, checks and tests the Code, then shows a version card.
  You choose **Switch on** on that card.
- **In your editor and terminal:** `cld code` gives you a local folder with
  typed SDK files, so your editor completes every operation and input.

This page follows the terminal path with the invoice example from the
[overview](/en/code): Code of a fictional mailbox `invoices@` (ID `Mbx001`).

## Before you start

- Install the Code commands once: `cld plugins install code`.
- To create Code for a mailbox, you need **Manage** access to that mailbox.
  For personal Code, you need nothing extra.

## Create the project

```terminal ~/work
$ cld code init --title "Invoice desk" --owner-type mail.mailbox --owner-id Mbx001
Created c_7k2m. Run sdk pull in its directory.
$ cd code/mail/Mbx001
$ cld code sdk pull
SDK refreshed.
```

`init` creates the Code in Cloud and writes its folder. `sdk pull` writes the
SDK your installation generates for this owner. Folders are named after IDs,
never after titles:

```tree
code/
  mail/
    Mbx001/            # Code of the mailbox Mbx001
      code.json        # Code ID, title, owner, entry file, base version
      code.tsx         # the entry file; default-exports app
      lib/
        invoice.ts     # your own modules, imported with relative paths
      test/
        invoice.json   # a test case: fixed clock, seed, fictional replies
      sdk/             # generated by sdk pull; never edit
      tsconfig.json    # generated; makes your editor know @sdk
  me/
    c_4n8q/            # personal Code is named by its Code ID
      code.json
      code.ts
```

Resource Code starts with a `code.tsx` page, personal Code with a schedule in
`code.ts`. Code imports only `@sdk` and its own files. `code.json` connects the
folder to Cloud:

```json
{
  "version": 1,
  "codeId": "c_7k2m",
  "title": "Invoice desk",
  "owner": { "kind": "resource", "ref": { "type": "mail.mailbox", "id": "Mbx001" } },
  "entry": "code.tsx",
  "baseVersionId": null
}
```

## Write, check and test

Write the handler from the [overview](/en/code) into `code.tsx`, then let the
checker read it:

```terminal ~/work/code/mail/Mbx001
$ cld code check
Permissions
  mail.message.read           at application   code.tsx:6
  core.ai.decide              at application   code.tsx:12
  mail.conversation.read      at application   code.tsx:20
  mail.conversation.tag.update at own Mailbox Invoices (Mbx001)   code.tsx:21
AI           yes
$ cld code test
✓ test/invoice.json
```

The check lists every operation the Code can call, with its target and the
line that calls it. This list is what the administrator reviews and what Cloud
enforces later: a call that is not in it is refused at runtime.

A test case runs the real bundle in the same sandbox as production, but every
call goes to a fake. A missing fake fails the test; it never falls through to
real data. See [Test Code](/en/docs/platform/test-code) for the case format.

## Submit and switch on

```terminal ~/work/code/mail/Mbx001
$ cld code submit
✓ v1 uploaded, not switched on yet. No version is running.
  It waits for approval by a Cloud administrator.
# A Cloud administrator approves v1 because it uses AI.
$ cld code activate
Switch on version 1 of “Invoice desk”. The Code runs as its service account with its current target grants.
Switch on? [y/N] y
✓ v1 switched on by you · Nov 9, 2026, 4:20 PM
```

`submit` saves an immutable version. The running version, if any, keeps running
until a person switches on the new one. If someone else saved a newer version
first, `submit` stops with `code_version_conflict` and shows the difference;
nothing is overwritten.

One step is still missing: the mailbox's service account has no rights yet.
A manager of the mailbox shares it with the Code account (**Edit**, because the
Code changes tags). From then on, each new message starts one run. Read runs
and their calls on the mailbox's **Code** page or with `cld code runs`, and
stop new runs with `cld code pause`.

Personal Code runs as you, so it needs no share. You switch it on in the
browser: on the version card in Gustav or on its Code page.

## Change it later

Edit, check, test and submit again. Every submit is a new version with its own
review. For a project you do not have locally, `cld code pull c_7k2m --out ./fresh`
downloads the latest saved version into a new folder.
