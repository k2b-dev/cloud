### Messages with NUL bytes failed hydration on every attempt

- **What happened:** In production, one 5.4 KB `multipart/mixed` message, with 8bit inline text and a base64 attachment, failed hydration with `ERR_POSTGRES_SERVER_ERROR` on every attempt, also after a repair. Mail recorded only that code.
- **Root cause:** Hydration wrote the parsed text, the attachment names and the selected headers to Postgres as they came from the message. Postgres `text` cannot hold U+0000 (SQLSTATE 22021) and `jsonb` cannot hold `\u0000` (22P05), so the same write failed each time. Test messages shaped like the production one reproduced it: NUL in the 8bit inline text failed at the body's search text (`unnamed portal parameter $4`), and NUL in a quoted, RFC 2231 or encoded-word attachment name failed at the part's file name (`$8`). Invalid UTF-8 alone did not fail, because the decoder replaces it with U+FFFD. Suspected: the production message carries NUL in its 8bit inline part; its exact field is not confirmed.
- **Error class:** Untrusted mail bytes are written to Postgres text without normalization, so data the database cannot store fails the same write again and again.
- **Guard:** Hydration removes NUL and replaces lone surrogates (`toWellFormed`) in every text and `jsonb` value it writes: body text and search text, HTML, part and attachment metadata, selected headers, protocol facts and receipts. The stored source and attachment bytes stay unchanged, and the stored text is the text the reader shows. The reader drops NUL from a `cid:` reference the same way, so inline images still match. Every hydration failure log line names the SQLSTATE, the refused parameter number, and the table, column and constraint that Postgres reports, never a value or the rest of Postgres' context. `message-hydration-text.integration.test.ts` has one fixture per place: NUL and invalid UTF-8 in the 8bit inline text, in the base64 text attachment, in an RFC 2231, encoded-word or quoted file name, and in headers. The NUL fixtures fail before the fix. The test also checks the failure log.
