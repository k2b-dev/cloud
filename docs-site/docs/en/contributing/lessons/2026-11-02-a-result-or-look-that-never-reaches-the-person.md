### Code review and Code page results stayed out of view or unstyled

- **What happened:** After approving a Code version the result notice rendered at the top of a detail column the page had scrolled down, and focus stayed on the page body. The line jump in a review scrolled the whole Administration workspace. Row titles on every Code page used the page-title size, and links in Spaces card history and in the review rendered as plain text.
- **Root cause:** The `Tabs` file strip scrolled its ancestors on mount, and `CodeDiff` and the review revealed a line with `scrollIntoView`, which moves every outer scroller. `.cloud-code__title` was defined twice, for the page h1 and for row titles, so the first rule's size reached every row. `k2b-link` is not a class any stylesheet defines; the shared class is `k2b-text-link`.
- **Error class:** A result shown somewhere other than where the person acted without moving focus there; one class name used for two roles; a class name that styles nothing.
- **Guard:** `CodeArea.browser.test.ts` approves from a scrolled review and requires the result in view with focus, and requires a line jump to scroll only the detail column; `code-diff.browser.test.ts` requires a mark to leave the outer shell alone. `MailboxCode.browser.test.ts` fails when a Code row title is larger than its section heading. The `ui-classes` check (UI-29) fails on any `k2b-*` class in app markup that no shipped stylesheet defines.
