### Editor UI followed the selection instead of focus: marks on open, raw blocks after blur, a returning bubble menu, a stale caret

- **What happened:** Opening a note showed the heading mark before its title, and an image, formula or table in the first lines showed its source, although nobody had clicked into the editor. After a click elsewhere, the block last edited stayed raw. The bubble menu came back after Escape as soon as a collaborator typed, and the others kept seeing a person's caret after focus had left the editor.
- **Root cause:** The Markdown decorations of `@k2b/editor` revealed source wherever `state.selection` stood, and CodeMirror's default selection at position 0 sits on the title line. `BubbleMenu` compared the dismissed selection by object identity, which every remote change replaces. `remoteCursors` cleared the published cursor only in a branch that required focus, which it never had there.
- **Error class:** UI state derived from the selection alone, without the editor's focus or a value comparison that survives document changes.
- **Guard:** `reveal-focus.behavior.test.ts` checks for every preview extension that a block at the start renders without focus, shows its source with focus and renders again on blur; `cursor-zone-field.behavior.test.ts` covers marks, a press that focuses, and decorations added to a focused editor. `BubbleMenu.browser.test.ts` and `collab.behavior.test.ts` cover the menu after Escape and the withdrawn caret.
