### The flat detail column, sections, and areas were restyled instead of rebuilt

- **What happened:** The maintainer rejected the flat UI as "restyled, not rebuilt": an alert cell in the detail column stood 20 px inside its column, a detail topic was 177 px where the mockup has 149, value rows were 36 px instead of 32, a section head was 28 px instead of 20, and a page that an app put into `DetailPanel.Body` never reached the edge. A team rebuilding a record page found the same in `Section`, `Area`, line `Tabs`, `ProgressPath`, `SegmentedControl`, and a date field.
- **Root cause:** The shared blocks kept their old nesting and only got new colours. `DetailPanel.Body` indented every child it did not know by class name and padded itself; `Section` padded its body, so a table or an alert inside could not reach the edge; heights came from content plus padding instead of the height tokens. Tests measured the blocks against themselves, never against the mockup's numbers.
- **Error class:** A container that holds the text edge for its children (padding or margin by class list), and heights derived from content instead of tokens, measured without the mockup's values.
- **Guard:** One `data-k2b-band` contract instead of class lists: a band reaches both edges and holds its own text edge; the body and a page section add none. `packages/ui/src/layout/flat-primitives.browser.test.ts` renders every block at 1440 and 390 px and asserts the mockup's numbers (text edge 20/16, topic 16/20/8 and 148 px for three values, value row 32, alert cell edge to edge with its sign on the text edge, page head band 52, area gap 8, a slim path line through 10 px dots, controls inside their column) with `layoutProblems({ flat: true })` clean.
