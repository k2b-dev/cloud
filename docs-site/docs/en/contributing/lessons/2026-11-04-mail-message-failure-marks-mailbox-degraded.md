### One message that failed to load marked its whole mailbox as degraded

- **What happened:** A production mailbox showed **Needs review** with the reason "1 message failed hydration" in its mailbox health, the CLI `mail status` and the `/health` API, although its account, connection and folder syncs worked.
- **Root cause:** `getMailboxOperationalHealth` derived `degraded` for an active mailbox as soon as one message had `hydration_status = 'failed'`. The stored mailbox health stayed `active`, so sync scheduling, the hydration of other messages and the sidebar were not affected. The state was a false alarm, but it read as if the whole mailbox needed attention.
- **Error class:** The state of one item is raised to the state of its container, so a local failure reads as a failure of everything.
- **Guard:** The operational health now reports the stored mailbox health; `hydration.failed` still counts failed messages, and the mailbox health shows that count quietly in its summary row. `provider-lease-fairness.integration.test.ts` fails one message for good and requires that the other bodies load, that new mail still arrives, and that the health stays `active` with `hydration.failed: 1`; with the old derivation it fails. The reader behavior test checks that the failed message offers **Try again**, which requests that one message with priority. `MailOperationalSettings.behavior.test.tsx` checks the quiet count next to the **Active** badge.
