### Text typed into the chat field before the island mounted was lost

- **What happened:** A person opened an empty Gustav chat by its address and typed the first message while the page was still loading. Nothing was sent, and the chat stayed empty. A chat made with `cld assistant chats create` was also called "New chat" for a German person.
- **Root cause:** `@k2b/ssr` does not hydrate islands; `mount.ts` clears the server markup and renders the island again. The server's `<textarea>` takes typing before that, and the new markup replaced it with an empty field. A first fix in `ChatComposer` assumed Solid hydration and never ran in Cloud; the walkthrough after it still lost the text at `domcontentloaded`. The create route left an untitled chat to the store's English default title instead of the request locale.
- **Error class:** A framework that re-renders server markup drops state the person created in it meanwhile; a fix tested against a mount model the product does not use; a server default text that ignores the request locale.
- **Guard:** `mount.ts` carries text the person typed (recorded by a trusted-`input` listener that `html()` writes) to the same field of the new markup, found by identity and place, with `input` and `change` events, focus, and selection; `packages/ssr/test/engine/island-typing.engine.test.ts` covers prefilled and emptied fields, a restored draft, disabled and missing fields, browser-set values, and two islands, through the real mount. `packages/cloud/src/ai/routes.integration.test.ts` creates an untitled chat in German and English. Test a mount fix through `@k2b/ssr`'s real mount, not through Solid's `hydrate`, and have a second reviewer read changes that reach every application.
