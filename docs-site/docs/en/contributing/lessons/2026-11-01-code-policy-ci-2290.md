### Policy persistence and presentation need checks at their public seams

- **What happened:** Code policy integration fixtures stored a JSON string instead of a manifest object. German input descriptions were also missing from the new capabilities.
- **Root cause:** Already serialized JSON was bound directly to a jsonb parameter, causing Bun SQL to encode it again. Local checks omitted the built-in registry presentation test.
- **Error class:** Transport encoding and required metadata are assumed instead of verified at the database and capability boundaries.
- **Guard:** Policy integration tests assert that manifests and both initial and continuation outbox snapshots are JSON objects and exercise batch pauses. The built-in presentation test checks German registry text and object input descriptions; the focused Core manifest test requires a review for every Code Action with policy and compiles the complete manifest.
