### A storage retry test lost its reconnect when the backoff hit its cap without jitter

- **What happened:** "Yjs provider storage exhaustion > reports the error, retries a bounded number of times, then stops" failed in a merge group (`unit (1)`) with `timers.shift() is not a function`: the hand-collected list of timers was empty before the test had run all its retries (#4432).
- **Root cause:** The test's `setTimeout` stub sent every timer with a delay of exactly `SHARED_TEXT_ACK_TIMEOUT_MS` (30,000 ms) to the real `setTimeout` and collected the others. The fifth reconnect's backoff is capped at 30,000 ms plus `floor(Math.random() * 1,500)` jitter, so about one run in 1,500 the reconnect had exactly that delay, went to the real timer, and the list ran empty. Load had nothing to do with it; `Math.random() = 0` reproduces it every time.
- **Error class:** A fake timer told apart by its delay value, where a computed (backed-off, jittered) delay can equal the sentinel delay.
- **Guard:** The test runs on a fake clock that knows each timer by its id (with `clearTimeout`) and runs exactly the one reconnect each close scheduled, asserting one per close for `MAX_STORAGE_RETRIES` closes and none after the last. It pins `Math.random() = 0`, the case that broke (`provider.test.ts`, red before with the original error). The other tests that route timers by this delay stay below the backoff cap (at most four reconnects, 16,000 ms), so they cannot meet it.
