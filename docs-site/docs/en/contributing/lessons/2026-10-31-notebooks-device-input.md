### Unconfirmed Notebook input must survive the tab

- **What happened:** Notebooks lost unconfirmed typing when a tab was discarded, crashed, or closed without an unload event. This included first edits before collaboration started and input retained after “Sync ended”. The browser regression reproduced an empty device-generation list after typing while the server refused writes: expected `["0"]`, received `[]`. With the original Notebooks provider, the integration regression also failed at `expect(device).toBeDefined()` with `Received: undefined` after continuous typing and socket drops.
- **Root cause:** CodeMirror's first-input buffer and the provider's recovery input lived only in memory. Leave prompts could warn about navigation but could not preserve those bytes when the browser stopped the page.
- **Error class:** Unconfirmed input kept only in memory relies on unload prompts that browsers do not guarantee.
- **Guard:** `offline.browser.test.ts` mounts the actual Notebook editor with real IndexedDB and WebSockets, closes and reopens the page, and covers deletions, terminal recovery, storage failure and retry, account changes, older generations, and committed receipts. `offline-input.integration.test.ts` drives the real Notebook provider and application admission/store during continuous typing, HTTP edits, reconnects, and a fresh session; it checks both Markdown and the committed Yjs snapshot. Device records are removed only by a covering durable receipt or an explicit discard.
