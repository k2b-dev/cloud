### Live delivery repeated database decisions after a cache expired

- **What happened:** A channel with a one-statement access decision ran one SQL statement again on the first delivery after every two-second cache window.
- **Root cause:** The delivery cache was the only available channel mode, even when every decision input already published an access event.
- **Error class:** Database-backed authorization in a live delivery hot path.
- **Guard:** `events/live-budget.integration.test.ts` pins an explicitly event-only channel to two setup statements, zero delivery and progress statements at +1, +2001, +4002, and +60001 ms, and two statements per affected Identity-Access event with none for unrelated subjects. Default-mode and event-driven admission and revocation tests preserve both contracts. Subject-isolation tests cover admission and collection refresh during unrelated identity events; bounded prefetch tests retain eight concurrent periodic decisions, ordered delivery, and correct admission of viewers joining during prefetch. Domain-burst tests cover key-specific admission and deferred collection refresh without disconnecting readers. Chat reader budgets cover lazy invalidation and fail-closed delivery. A blocked-owner regression test keeps other keys moving after authority expires; live checks only consume cached authority, and HTTP renewal tests cover deduplicated reads and outdated responses. DATA-13 requires a measured budget and complete event coverage before opting out of polling.
