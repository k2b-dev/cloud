### Pin calendar labels using the native scroll range

- **What happened:** Calendar pinning could mix a CSS container-query estimate of overflow with the native `scrollLeft`. An unconditional native override then changed first-render inline styles, failing the showcase's server/client markup check. A separate WebKit origin-gap assertion mixed Playwright's SVG text quad with DOM cell rectangles.
- **Root cause:** The scroll handler wrote its override even when CSS already matched the scrollport, and the gap assertion compared two APIs with different SVG text extents.
- **Error class:** Mixing coordinate sources, and unnecessarily mutating initial markup.
- **Fix:** Keep the CSS estimate when it matches the native scroll range. Resolve that estimate in the SVG's query-container context; apply a native override only when the two differ, refreshing on scroll, resize and drawing replacement. Use DOM client rectangles for both text and cells when measuring padding, with the SVG text anchor as an independent check. The shared inspector remains unchanged.
- **Guard:** The existing browser file requires the resolved CSS overflow to equal the native range at both scroll ends and after resize. It reproduces a changed query container whose estimate differs by 34px from the scrollport. First-render inline styles and pinned text boxes must match the server frame. The origin gap remains bounded by 8px and the text's right edge must coincide with its transformed SVG anchor. The unchanged showcase hydration checks compare full island markup. Real-panel fixtures cover 390, 800, 1440 and 1920px. WebKit execution remains a CI check because this VM lacks its host libraries.
