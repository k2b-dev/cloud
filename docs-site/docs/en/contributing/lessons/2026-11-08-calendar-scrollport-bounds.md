### Pin calendar labels using the native scroll range

- **What happened:** WebKit left a 13.125px weekday-to-grid gap even after scrolling the calendar to its oldest week. Measuring at a defined origin alone did not resolve the defect.
- **Root cause:** Calendar pinning combined a CSS container-query estimate of overflow with the native `scrollLeft`. Those two coordinates need not share the same reference box. The column-alignment modulus amplifies a difference into a visible rail offset. The Chromium regression changes the nearest query container without changing the scrollport: the old module reports 706px while the native range is 740px.
- **Error class:** Mixing CSS query coordinates and native scroll coordinates.
- **Fix:** Keep the CSS estimate for the server frame. Once mounted, derive overflow from `scrollWidth - clientWidth` in the calendar-owned module, and refresh it on scrolling, resize and drawing replacement. The shared inspector remains unchanged. Disconnect observers and clear owned properties on teardown.
- **Guard:** The existing browser file requires the resolved CSS overflow to equal the native range at both scroll ends and after resize. The query-container mismatch fails with the old module and passes with the fix. The 8px gap bound remains unchanged. All pinned text boxes must also match before and after mounting, including the real-panel fixtures at 390, 800, 1440 and 1920px. WebKit execution remains a CI check because this VM lacks its host libraries.
