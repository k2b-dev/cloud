### Pin calendar labels using the native scroll range

- **What happened:** Calendar pinning could mix a CSS container-query estimate of overflow with the native `scrollLeft`. An unconditional native override then changed first-render inline styles, failing the showcase's server/client markup check. A separate WebKit origin-gap assertion mixed Playwright's SVG text quad with DOM cell rectangles.
- **Root cause:** CSS query lengths retain fractional pixels while native scroll widths are integers. Even a conditional inline override therefore changes hydrated markup in WebKit; the gap assertion also compared two APIs with different SVG text extents.
- **Error class:** Mixing coordinate sources, and unnecessarily mutating initial markup.
- **Fix:** Keep CSS as the server fallback and store the native range and scroll offset in a calendar-owned CSSOM rule scoped to its generated id. Refresh it immediately at mount, on scroll, resize and drawing replacement, without changing serialized style declarations. Remove its adopted stylesheet on teardown. Use DOM client rectangles for both text and cells when measuring padding, with the SVG text anchor as an independent check. The shared inspector remains unchanged.
- **Guard:** The existing browser file requires the resolved CSS overflow to equal the native range at both scroll ends and after resize. It reproduces a changed query container whose estimate differs by 34px from the scrollport. First-render inline styles and pinned text boxes must match the server frame. Additional fractional-width cases compare the entire server-rendered chart element byte for byte before/after mounting and scrolling, check the native range at both ends, and verify stylesheet cleanup. The origin gap remains bounded by 8px and the text's right edge must coincide with its transformed SVG anchor. The unchanged showcase hydration checks compare full island markup. Real-panel fixtures cover 390, 800, 1440 and 1920px. WebKit execution remains a CI check because this VM lacks its host libraries.
