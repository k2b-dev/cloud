### Mailbox sharing kept a parallel editor, and a global font rule hid monospace

- **What happened:** Mail's mailbox settings and the admin repair action shared a mailbox through an inline editor of their own, with its own **Search** step, hits without description or mark, and Code accounts mixed into the people list. The shared access dialog cut its **Add service account** label on phones and left a service account picked from the search for people out of view. Every Code handle and every other `<code>` in Cloud rendered in the sans face.
- **Root cause:** Mail mounted the editable `PermissionEditor` instead of `openAccessDialog()`, so later changes to the dialog never reached it. The dialog hid the long label below `sm` and scrolled only for the handle field. Cloud's `global.css` sets `font-family` on `*` outside a cascade layer, which overrides the `@k2b/ui` base rule for `code`; the browser tests measured with a fallback font, so widths looked tighter than in the product.
- **Error class:** A shared UI path is copied into one app, or a global rule overrides a library's base contract, and the copy drifts from the approved design.
- **Guard:** `resource-sharing.behavior.test.tsx` reads every real share entry and fails when it mounts an editable `PermissionEditor` or opens no shared dialog; `MailboxSettingsDialog.behavior.test.tsx` walks Mail's tab through the shared dialog. `AccessDialog.browser.test.ts` and `CodeAccountHandle.browser.test.ts` load IBM Plex and check the full label, the scrolled row, the monospace handle and its wrap; the same file checks that an explicit `font-sans`, as on Mail's plain-text bodies, keeps the sans face.
