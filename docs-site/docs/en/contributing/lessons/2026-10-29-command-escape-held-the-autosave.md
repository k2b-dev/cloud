### A Command Escape test held the draft's autosave instead of the opening's own save

- **What happened:** In WebKit, `Assistant full-view Command Escape restores editing during create|save` in `packages/chat/src/frontend/ChatPanel.browser.test.ts` failed at random: the composer was not read-only after the held request, and the next case found a second conversation (#2095).
- **Root cause:** The test held every create or draft save. The composer's debounced autosave of "Plan /" can start just before the command is chosen. A trace of a failing run showed that the held request was that autosave, not the opening's save. Saves of one draft are serialized, so the opening waited behind it. The test also read `readOnly` once instead of waiting for it, and it released the held request before closing its context, so the request reached the shared fixture after the next test had reset it.
- **Error class:** A test intercepts requests by URL and method alone, so it can hold a background request of the same kind instead of the one it means.
- **Guard:** The test holds only requests that start after the command is chosen, waits for `readOnly`, and closes the context before it releases the gate. A WebKit check confirmed that a request released after `context.close()` no longer reaches the server; released before, it does. A rarer remainder in the create case stays open in #2095.
