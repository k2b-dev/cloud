### Measure settled server geometry without repeated browser document scans

- **What happened:** The calendar overview test timed out at 5 s in the merge group for #3120, after the native CSS selector fix for #3021. Calendar, distribution and Sankey geometry tests still loaded the full chart overview for each viewport.
- **Root cause:** Test overhead remained after replacing Playwright's `has` filter. Local WebKit profiling measured 4.4–6.6 s for the intercepted overview navigation, 0.3–0.5 s for settling, 82–255 ms for reading the response, 134–206 ms for parsing the entire response again, and up to 2.2 s for a locator-based markup read. A direct DOM geometry read took 5–8 ms. Setting the script-blocking CSP in the fixture server avoids the Playwright fetch/fulfill round trip; extracting the calendar SVG in Bun avoids transferring and reparsing the full document. Distribution and Sankey tests had the same repeated locator-read pattern.
- **Error class:** Browser test setup and repeated document scans consume the assertion budget on a large real page.
- **Guard:** The existing calendar, distribution and Sankey tests retain their viewport coverage, SVG comparison, geometry assertions and unchanged 5 s limits. They read each settled document with one native DOM measurement and normalize only the extracted server SVG. All 16 geometry cases passed locally in WebKit; overview cases took 2.7–3.9 s. Keep independent viewport tests: resizing preserved the exact calendar SVG, rectangles and scroll position, but each width change plus settling cost another 1.4–1.6 s, so combining all widths would exceed the same test budget.
