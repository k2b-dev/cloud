### A shared Mail browser test had never run against its own bundle

- **What happened:** On #1737, all four cases in `packages/mail/src/frontend/_components/mail-draft-document.browser.test.ts` timed out in Chromium and WebKit while waiting for `mailSharedFixture.state().ready`. The suite was written while browser runs were deferred and had not run before CI. Behind the first error were three more: a nested `EditorView.update` crash, a redo shortcut that never arrived, and a fixture draft whose principals were not UUIDs.
- **Root cause:** The harness bundled the page as one IIFE. Bun wraps modules reached through a dynamic `import()` in lazy initializers and dropped the initializer call for `@k2b/stdlib`, which declares `sideEffects: false`. `encoding` stayed `undefined`, so the shared session never started. After that, the shared `TextEditor` re-ran `setReadOnly` from reactive session state that changes inside an editor update and dispatched although the value had not changed.
- **Error class:** A browser harness bundles differently from production islands, so the test fails before it reaches the behavior it describes, and the failure looks like a timeout.
- **Guard:** The harness builds split ES modules like `packages/ssr/src/build.ts` and serves every chunk. The editor engine dispatches `setReadOnly` only when the value changes. The suite now covers both, together with Mod-Home and Mod-End from a table cell.
