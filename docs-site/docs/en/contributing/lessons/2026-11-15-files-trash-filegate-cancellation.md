### A Docker initializer outlives its abort signal

- **What happened:** PR #3476 failed the Files trash-activity suite's setup after 30 seconds, before any named case ran. Bun reported an unnamed hook timeout and killed one dangling process (#3479).
- **Root cause:** The Filegate fixture used the default SIGTERM when its startup deadline expired. An attached `docker run` forwards that signal to its container and continues waiting if the container does not exit. A real Debian initializer that ignores SIGTERM reproduces the dangling subprocess with CI's Bun 1.4.4. The original log does not identify the Docker command or explain why its container stalled.
- **Error class:** A cooperative subprocess signal is treated as a guaranteed deadline, allowing dependency setup to wait beyond the test budget.
- **Guard:** `activity-filegate.integration.test.ts` aborts an attached real Docker initializer after it installs a SIGTERM handler and requires the CLI promise to reject. The fixture kills the CLI with SIGKILL and removes its owned resources separately. Cleanup shares one five-second budget, keeping startup plus cleanup below the unchanged 30-second hook deadline. The trash suite deletes its prefix separately only on a configured shared Filegate; its isolated volume is already removed by fixture cleanup. Trash setup runs once through a cached promise in `beforeEach`, so a setup failure is attributed to a named case, including when a case is selected by name.
