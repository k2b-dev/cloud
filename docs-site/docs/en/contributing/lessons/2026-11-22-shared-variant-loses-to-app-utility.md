### A shared variant lost its value to an app's own plain utility

- **What happened:** Warenfluss found, and the flat-design QA confirmed, that shared Cloud variants lost on its pages as soon as its own sheet emitted the plain utility: `sm:gap-2` in the breadcrumbs next to `gap-1`, `md:px-3` and `md:py-2` in the header next to `px-2 py-1.5`, and `dark:text-zinc-600` in the breadcrumbs and footer next to `text-zinc-400`.
- **Root cause:** Since #3928, an app's `app.css` loads after `global.css`, and both put their utilities in `@layer utilities` at equal specificity. A shared class list such as `gap-1 sm:gap-2` therefore breaks wherever the app's sheet repeats `gap-1`: the later plain rule beats the shared `sm:gap-2`. UI-28 (`breakpoint-display`) guarded only `display`; 90 pairs on other properties and with `dark:` remained in `@k2b/cloud`, and 7 in `@k2b/editor`.
- **Error class:** A plain utility and a variant of the same property on one element, in markup that renders under another stylesheet that may repeat the plain utility later in the same layer.
- **Guard:** `scoped-variants` replaces `breakpoint-display`. It reads Cloud's Tailwind setup and reports a plain utility next to a variant on the same element at the same specificity that sets one of its properties, shorthands included (`p-2` with `md:px-3`), in `packages/cloud/src`, `packages/ui/src` and `packages/editor/src`. Shared UI scopes both sides (`max-sm:gap-1 sm:gap-2`, `not-dark:text-zinc-400 dark:text-zinc-600`), which looks the same in either stylesheet order.
