### The v2 select typeahead test chose the option that was already highlighted

- **What happened:** In the merge queue the browser test "select: typing the start of an option chooses it with Enter" got "Neubau" instead of "Montage" (#4126). The PR in that group did not touch the select.
- **Root cause:** The test typed "Mo" and pressed Enter as soon as the list was visible. It never waited for the state its Enter relies on, the highlight on "Montage". On a loaded runner the keys reached the list before it took them, and Enter chose the option that was still highlighted.
- **Error class:** A browser test acts on a state it assumes instead of waiting for it: it presses as soon as something is visible, not when the result of the step before it shows.
- **Guard:** The test waits for a highlighted option before it types, and for "Montage" highlighted before it presses Enter (`packages/ui/src/v2/overlays.browser.test.ts`). No repository rule fits: `test-waits` catches fixed sleeps and `settle-reads` catches measuring right after an action, but which state a step needs depends on the widget. After typing into a field the value is there at once; after typing into a list the highlight moves in the list's handler. A pattern rule on `keyboard.type` followed by `press` would flag every form field. The convention stays as in [Testing](../testing.md): wait for the test's own condition before the next step.
