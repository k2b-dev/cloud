### Core's tests in test/ were never typechecked, so a stale import there reached CI

- **What happened:** In #4174 a renamed Core admin island left `packages/core/test/account-operations.behavior.test.tsx` importing a file that no longer existed. Neither the package typecheck nor the local admin runs saw it; only the unit shard in CI failed. Typechecking the folder then showed 10 more errors that had built up unseen, and one of them hid a test that did not check the production path.
- **Root cause:** `packages/core/tsconfig.json` included `src` and `scripts` but not `test`. Test doubles drifted from their types: toast stubs returned a string instead of a `ToastHandle`, and a `MutationObserver` came from the harness window instead of the global. The consent test mounted the form without its required `userId`, so the cancel case signed out an anonymous session, a path the page never takes.
- **Error class:** A test folder outside a package's typecheck `include` lets imports and test doubles drift from the code they test, and the drift surfaces only when the file runs, or not at all.
- **Guard:** `packages/core/tsconfig.json` includes `./test`, so `bun run --cwd packages/core typecheck` covers those files. The consent test passes the form's `userId` and checks the form's own promise: it signs out its person, then moves on. The sign-out itself is covered by `packages/cloud/src/browser/session.test.ts`.
