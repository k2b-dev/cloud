### A rule written for one kind of entry misses the next kind

- **What happened:** The P4 tour of the Gustav preview showed the chip "Version 2 einschalten" above the field while its version card was in view, "Waiting for you" offered only "Choose a chat …" for an automation whose chat was archived although its Code page offered "Restore chat", and the Spaces task block read "Task", "Deadline None" and "Assignees None".
- **Root cause:** The quiet rule of the row was written for one approval with its tool block and required it to be the only entry overall, so a version card or any entry of another chat kept the chip. The waiting feed carried no archived chat, so the page could not offer what the Code page offers. The task block used the kind as its title and wrote empty facts as a word instead of leaving them out.
- **Error class:** A rule or a presentation built for the first case is not extended when a new kind of entry or an empty value joins it.
- **Guard:** `waiting-questions.test.ts` and `AssistantWaitingStrip.render.test.ts` cover a version card and entries of other chats; the render fixture's case "two" now expects only the other chat's entry. `AssistantCodeView.render.test.tsx` covers the archived and the deleted chat, and `chat-binding.integration.test.ts` pins `archivedChat` in the feed. The Spaces task-reader test asserts the task's title and no "None" in either language.
