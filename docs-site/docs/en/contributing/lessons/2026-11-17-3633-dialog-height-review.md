### Observe natural content and preserve the visible start of a dialog fold

- **What happened:** Growth moved a dialog upwards before its first animated frame. Loading buttons prevented failed-save notices from folding, keyboard filtering moved focused fields, viewport changes and mode changes lost placement, and a fold could overwrite an explicit position. Replacing a 500-node preview also caused frame measurements and 1,000 resize-observer registration calls per keystroke despite unchanged height.
- **Root cause:** Re-review also exposed overly broad input focus detection, a focusout fold moving a pressed footer button, lost removal and mid-fold natural-size signals, and an unchanged position observer interrupting folds. Arrival retention and observation descended beyond the stretched shells. The initial top keyframe used the destination edge. Busy detection included controls, observation followed every descendant and mutation, and presentation and motion both wrote positioning without coordinating ownership. The first resize report was treated only as a baseline. A zero percentage flex basis on the scrolling body also let WebKit retain its previous intrinsic height after a pinned frame was released; a content basis keeps that measurement current. The test helper also took its animation snapshot before that first report could schedule the frame’s measurement.
- **Error class:** Layout observation and animation ownership races.
- **Guard:** `packages/ui/src/feedback/dialog-height.browser.test.ts` samples the held first frame and intermediate edges, exercises a real loading Button and phone RichSelect, checks resize, adaptive anchors, first rest, focused and moved content, child height motion, mode and position changes, and a size change before the first observer delivery. An unchanged initial observation also leaves the entrance layout-free. Its 500-node fixture requires zero frame layout reads and zero observation registration calls per unchanged-height keystroke. `packages/ui/test/browser.browser.test.ts` schedules next-frame motion from the helper's own first fonts read and holds its clock until the helper awaits it, so the old snapshot reliably fails instead of depending on the gap between browser RPCs. A second deterministic schedule waits for the first size delivery before starting motion; the helper includes that one initial observation wave and still rejects animations that keep starting afterward.

The re-review guards hold motion at creation and assert retargeting before the previous completion, footer click delivery, focus interruption, busy/pre-rest shrinking, pinch exclusion, bounded arrivals and row observation, and real ChatTasks grid motion. `packages/cloud/src/browser/spotlight-position.browser.test.ts` composes the real position observer with ordinary dialog motion and advances it through several size-report cycles.

The unchanged Assistant settings and secrets tests also exposed a close during an arrival fade whose notice had already disappeared. Chromium rejects `commitStyles()` on an unrendered target, interrupting close before its result resolves. Freezing now preserves only rendered fade targets and cancels every fade. Held-clock guards remove or hide the notice before closing and assert that no unrendered target is committed and the dialog closes.

CI also caught fractional natural heights rounded by `offsetHeight`: holding that integer moved a centred dialog by half the rounding error. Frame geometry now uses fractional layout border boxes, independent of CSS zoom and transforms, with an exact before/after holding guard. The pointer barrier also covers a running fold and natural-size reports without focusout; a held-pointer unstructured-form guard requires a stopped frame, no retarget before release, stable button geometry, and delivered native submit. The real machine-key retry remains an unchanged consumer guard; the single CI timeout alone does not establish that this was its cause. Chat’s existing preload budget guards removal of duplicate eager motion initialization/announcement paths, and the phone RichSelect guard moves the pointer off its trigger before settling.

The next review covers lost pointer releases (blur, capture loss, hidden document and later button-free pointer events), final-size positioning of a bottom-clamped Spotlight, retrying a failed lazy import for the existing dialog, and fractional frame heights under CSS zoom and scale. Automatic consumers skip intermediate frame reports and clamp on `k2b-frame-resize`; explicit positioning still wins. Browser guards cover recovery and scaled geometry, the real Spotlight observer checks one final clamp, and a rejected-then-restored import behavior guard requires a single initialized motion following the current level.
