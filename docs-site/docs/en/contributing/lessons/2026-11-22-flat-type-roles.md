### The flat UI showed more text sizes than the mockup

- **What happened:** The maintainer rejected the flat UI because it showed many more text sizes than the approved mockup. The mockup uses four sizes (12, 13, 14, 18 px) and three weights. The built pages also showed 10, 11, 12.5, 13.5, 15, 16, and 20 px and the weights 650 and 700. Most of these came from `@k2b/ui` building blocks such as `StatusBadge`, `Tag`, the sidebar meta, `Discussion`, and `Kbd`.
- **Root cause:** The four size tokens existed (`--k2b-font-size-meta|row|body|lead`), but nothing made a building block use them. About 1,000 `font-size` declarations in `@k2b/ui` still set literal sizes from before the flat concept, and no check or test compared a rendered page with the four sizes.
- **Error class:** A design rule that exists only as tokens and prose drifts. Each building block keeps its own literal values, and a review of single components does not see the total number of sizes on a page.
- **Guard:** The `type-scale` rule (`scripts/checks/type-scale.ts`) allows no text size outside the four roles in `@k2b/ui`. Only signs, reading text, print, and the 16 px touch-field size are exempt, or a declaration with a named `type-scale: allow` reason. App findings are listed in `type-scale.baseline`, which can only shrink. `type-scale.browser.test.ts` renders a flat sample (shell, list, detail, badge, tag) in Chromium and fails on any other size or weight.
