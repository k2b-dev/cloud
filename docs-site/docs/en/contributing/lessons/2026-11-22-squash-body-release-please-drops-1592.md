### The release check passed a squash body that release-please dropped once wrapped

- **What happened:** release-please 17.6.0 dropped the squash commit of #3998 (`fix(chat): …`) from the 0.84 changelog without a warning: `unexpected token '(' at 15:17`. The PR's `check-release-pr-body --message` step had passed. It was the fifth such case that the release lane caught by hand (#1564, #2495, #2611, #3680, #3998).
- **Root cause:** The squash merge wraps each body line longer than 72 columns. In #3998 that moved `` `importOnDemand(() => import(…))` `` to a line start, and release-please's parser reads a line that starts with a word and `(` as a broken footer. The `--message` mode only linted the unwrapped title and body for markup and never ran the parser on the message that lands on `main`.
- **Error class:** A check that tests a stand-in for the text, here the unwrapped body, instead of the exact text the consumer parses, here the wrapped squash message.
- **Guard:** `check-release-pr-body --message` builds the squash message as the merge writes it (`squashMessage` in `scripts/release-pr-body.ts`), parses it offline with the `parseConventionalCommits` and `filterCommits` of the `release-please` root devDependency, which the `release-please-version` check keeps on the version that `main.yml` pins, and fails on a dropped part, a missing title entry, or an extra changelog or breaking entry. `scripts/release-pr-body.test.ts` reproduces the real squash commit of #3998 byte for byte. The `--self-test` cases cover #3998, its override, #1564 and #1578.
