### A CLI plugin test packs its fixture inside the 5 s test deadline

- **What happened:** In CI, `served-plugins.test.ts` › "plugin access errors, reserved names, and package plugins stay distinct" timed out after 5 s on a pull request that did not touch `packages/cloud-cli`. Bun then killed the running `cld plugins remove echo` child, so the test reported exit code 143 (SIGTERM) instead of 0.
- **Root cause:** The SIGTERM came from Bun's test timeout, which kills the child processes of a test that are still running. The remove path has no unbounded wait: it uses no network, and its lock waits are uncontended and end after 15 s. The test packed the echo plugin itself with `buildEchoPlugin`, a separate Bun process that bundles the fixture. Measured locally, the pack took 574 ms of the test's 1.3 s, and each of the nine `cld` starts took 60 to 140 ms. On a CI runner that was about five times slower at that moment, the test needed 6.2 s.
- **Error class:** A test counts a shared fixture build in its own deadline, so a slower runner turns the build time into a timeout of a later step.
- **Guard:** Convention in [Build shared fixtures outside test deadlines](/en/docs/contributing/testing#build-shared-fixtures-outside-test-deadlines): shared fixtures that start a process are built once at module scope. `served-plugins.test.ts` now packs the echo plugin once at module scope, as `plugins.test.ts` already did. Timeouts and budgets stay unchanged.
