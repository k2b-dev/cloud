### Two copies of the overlay scrollbar hung the Mail reader on the first hover

- **What happened:** With the overlay scrollbar as the default for the workspace columns, the Mail browser test "no sender, admin" timed out on a click. Playwright stayed in "performing click action", and a scripted `pointerover` on the reader hung the page as well.
- **Root cause:** `ScrollArea` attached the thumb when it mounted, and the workspace controller attached it again on the first hover. The two calls came from different copies of `@k2b/ui`, because each island bundles its own. Each copy remembered its thumbs in a module-level `WeakMap`, so neither copy saw the other's thumb. The two thumbs then took turns moving themselves to the front of the scroller. Each move was a new mutation for the other copy's observer, and the endless chain of microtasks blocked the page.
- **Error class:** A module-level registry is used to make DOM work idempotent, but the code runs in more than one bundle, so the registry does not cover every copy.
- **Guard:** `packages/ui/src/layout/overlay-scrollbar.behavior.test.ts` loads the module a second time and checks that a scroller still gets only one thumb. Without the fix, this test hangs. `attachOverlayScrollbar` now also asks the DOM whether the scroller already has a thumb. The Mail flat test hovers the list and checks the thumb and the text edge.
