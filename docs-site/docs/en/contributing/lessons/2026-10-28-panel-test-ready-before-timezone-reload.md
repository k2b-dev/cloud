### A panel test waited for a document that was about to reload

- **What happened:** In WebKit, `Assistant protects pending resource preparation (unknown creation: true)` in `packages/chat/src/frontend/ChatPanel.browser.test.ts` failed after about 8.8 s on unrelated pull requests (#1863, #2025; #2041). The report showed only a timeout in the failure diagnostics: `innerText` waited for the panel frame, which the test had not opened yet.
- **Root cause:** The real `ShellRuntime` writes the timezone cookie on its first mount and reloads the page once. The test context had no cookie. It waited for `fixture-ready` and then called `page.evaluate`. When the first document set `fixture-ready` before its reload started, the reload destroyed the execution context during that call. Then the `catch` block waited 8 s for a panel frame that did not exist and threw its own timeout, which hid the original error.
- **Error class:** A test waits for a readiness marker of a document that reloads itself once on first contact, and failure diagnostics wait on the page and replace the error they describe.
- **Guard:** All contexts in `ChatPanel.browser.test.ts` come from one `newContext()` helper. It sets the timezone and its matching cookie before the first navigation, so `fixture-ready` always belongs to the tested document. The `diagnose()` helper in the same file reads diagnostics with a 1 s timeout and logs a failed read instead of throwing it, so the original error is reported.
