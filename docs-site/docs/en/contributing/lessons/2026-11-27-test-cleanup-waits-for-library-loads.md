### A test's cleanup removed the window while the library still loaded the prompt fields

- **What happened:** A Spaces behavior test focused a tab and then called `cleanup()` from `packages/ui/test/dom.ts`. Shortly after, `@k2b/ui` reported "the form fields could not load" with `ReferenceError: window is not defined`. Spaces worked around it by importing the non-public `dist/browser/feedback/prompt-form-loader.js` and awaiting the load before its cleanup.
- **Root cause:** Without idle callbacks, the first focus, press or key starts the library's preload of the prompt form fields. The chunk runs after the import starts. Solid's `delegateEvents` in the chunk reads `window` while it runs. `cleanup()` removed the globals in between, so the chunk failed. A module that fails while it runs stays failed for the rest of the process, so no later form in that test file could load its fields either.
- **Error class:** A test harness that tears down its environment while work the library started on its own still needs that environment.
- **Guard:** The library tracks its own loads in one internal registry (`packages/ui/src/internal/pending-loads.ts`, a global key, so the source and the built package share it). Only the test harness creates the registry. A page has none, so production behavior does not change. `cleanup()` removes the DOM at once. While loads still run, it keeps the window until they end, or until the next harness starts and takes over the globals. `packages/ui/test/prompt-preload-cleanup.behavior.test.ts` failed before the fix and passes after it. It focuses a field, cleans up right away, and then loads the fields in a new harness.
