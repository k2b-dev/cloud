### Select test targets before capturing native platform clients

- **What happened:** After migrating Bun-global imports, integration tests used closed SQL pools, created Mail users and mailboxes in different databases, replaced live audit connections with unit doubles, and missed a concurrent Redis reservation replacement.
- **Root cause:** Native platform clients belong to the startup snapshot. Test setup changed that snapshot after service factories or Bun-global SQL fragments had captured the previous client. Audit tests installed offline unit doubles even during integration runs. A Chat test and a root transaction test spied on Bun globals while the owning Cloud services used platform clients. The logged NUL rejection came from an intentional invalid audit input; the failing tests did not demonstrate an encoding defect.
- **Error class:** Test setup and spies target a different connection instance from the service under test.
- **Guard:** The affected integration tests fail on stale captured pools, cross-database Mail writes, and missing transaction or reservation interception. Their setup selects the database before imports or factory construction and uses the owning service's client for setup, spies and assertions. Audit integration cases retain real clients. Separately, `packages/cloud/src/runtime/clients.integration.test.ts` compares native JSON and NUL-containing binary parameters across shared, owned and transactional pools; this verifies encoding parity rather than detecting fixture ordering.
