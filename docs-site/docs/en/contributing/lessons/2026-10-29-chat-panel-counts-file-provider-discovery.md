### A Chat panel test counted the file-provider discovery as a recovered catalog load

- **What happened:** In WebKit, `catalog and resource recovery in real panel at 1440px` in `packages/chat/src/frontend/ChatPanel.browser.test.ts` failed at random on unrelated pull requests and in the merge queue (#1876). It counted two recovered catalog loads instead of one, or timed out later in the same flow.
- **Root cause:** Besides the command menu, the panel document reads the capability catalog itself: `packages/cloud/src/browser/files.tsx` starts the file-provider discovery once the page is idle, in WebKit after a 1 s timer. The test's catalog route counted every successful read. When the discovery came after the test made the catalog recover, and before the count was checked, it became a second recovered load. The full-view cases already waited for that first read; the panel case did not.
- **Error class:** A test counts requests of a kind that a shared module also makes on its own.
- **Guard:** Every case waits for the first catalog read of the document it tests, which is that discovery, while the catalog still fails, before it opens the command menu. The count then covers only the menu's loads. The panel case passed 12 of 12 WebKit runs and 3 of 3 Chromium runs locally. #2080 answers this read for suites that do not serve the catalog; this file serves it, so it keeps its own wait.
