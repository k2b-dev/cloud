### An on-demand barrel import put unused code into every island

- **What happened:** The web Assistant island carried about 290 KiB of `@k2b/ui` and `@k2b/cloud` code it never ran, for example the bottom sheet, as bare `import"./chunk-…"` lines. The `island-bundles` budget had about 3 KiB left, so every addition to `@k2b/ui` counted against the Assistant (#3504). Built alone, the island had none of this code.
- **Root cause:** `PairingNotice.island.tsx` loaded the toast with `import("@k2b/ui")`, and `@k2b/ui` loaded its image helpers from the whole `@k2b/stdlib/browser` entry on demand. A static named import makes Bun read only the re-exports it names. An `import()` needs the whole namespace, so the barrel kept every re-export. Code splitting then assigned each module behind the barrel to every entry that imports the barrel statically, and such an entry imports the chunk even when it uses none of its exports.
- **Error class:** An on-demand import of a package entry that other browser code imports statically, which turns off barrel narrowing for the whole build.
- **Guard:** The repository rule `no-barrel-dynamic-import` fails on an on-demand import of a package entry that only re-exports other modules when other code imports it statically. `buildIslands()` warns about the same pattern for every application, including third-party ones, without failing their build. The `buildIslands() barrel imports` tests in `packages/ssr/test/unit/build.test.ts` cover the warning, prove that an unused, side-effect-free barrel module stays out of every island's static closure in the narrow form, and pin the Bun behavior. The affected call sites now import small local re-export modules on demand.
