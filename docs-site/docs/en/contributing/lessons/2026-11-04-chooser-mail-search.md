### The resource picker hid mails behind raw dates, alphabetical order and a silent cap

- **What happened:** Choosing a mail in the resource picker showed its date as `2026-11-04T13:31:20.000Z`, rows with only subject and first body line, so two mails with the same subject looked identical, and at most ten mails per mailbox. Core sorted each app's results by title, so mails appeared alphabetically, and nothing said that more mails matched.
- **Root cause:** Search result metadata had no type, so an app could only send a raw date string that it could not format in the reader's time zone. Core broke priority ties by title, which overrode an app's own ranking. Core cut every app's answer at its limit without asking whether there was more, and Mail additionally cut each mailbox to ten results and searched only the first 20 mailboxes.
- **Error class:** Silent truncation: a list that stops at a limit looks complete, because neither the producer nor the list says that more exists.
- **Guard:** Core now asks each app for one result more than it lists and streams `more: true`; the picker offers **Show more from …** up to 90 results and then asks for a narrower search. `search.test.ts` covers the order and the `more` flag, `CloudResourceSearch.behavior.test.tsx` and `CloudResourceSearch.browser.test.ts` cover loading more without moving rows and the dated details, and `capabilities.test.ts` in Mail pins newest-first order, the requested limit and the sender, recipients and date fields. Result metadata now takes `format: "date" | "date-time"`, so apps no longer format dates on the server.
