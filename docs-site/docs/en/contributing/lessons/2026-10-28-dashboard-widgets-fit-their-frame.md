### Dashboard widgets overflowed their fixed frames, and the first fix never landed

- **What happened:** On the dashboard, widgets showed a scrollbar inside their card, and the admin queue cut off its "Accounts · Groups" footer. A fix with a guard was opened on 23 October (#1807), but it never merged. Later commits added unrelated test repairs to it, the branch fell out of date, and nobody owned the landing, so people still saw the bug five days later.
- **Root cause:** A dashboard row has a fixed height. The `@k2b/ui` widget header grew by 9px with `meta`. Text inherited `line-height: 1.5`, which gives half pixels. Each block brought its own vertical padding. So a hero above a row of pills needed about 151px, but a medium frame gives its body about 120px.
- **Error class:** Content in a fixed frame is measured without its real spacing, fonts and scrollbars, and a fix stays open on a stale branch because unrelated work is added to it.
- **Guard:** Test: Dashboard `dashboard-home.browser.test.ts` renders every built-in widget from `built-in-widgets.browser-fixture.ts` in every size it offers, with long and short lists, in German and English, at 2000 to 320px. It uses Cloud's fonts and classic scrollbars. It fails on any body overflow, any block that ends below the frame (the footer included), and list rows narrowed by a scrollbar. Convention: a fix pull request carries only its own fix. Repairs to other tests go into separate pull requests.
