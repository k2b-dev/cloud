### A Mail draft test reported only "false" and hid which step failed

- **What happened:** In one merge-queue run, `shared sign-in preparation uses reload-safe document storage: storage-failed` failed with `Expected: true, Received: false` at `expect(f.session.authenticationRequired()).toBe(true)`. The file passes locally, also with Bun 1.4.4, under CPU load, forced garbage collection, delayed sockets and requests, and in the same 51-file process as the CI shard (#3846).
- **Root cause:** Suspected: a step before the save request failed once, most likely opening the shared draft client. The test cannot say which step. The suspected race between `persist()` and the sign-in state does not exist. A 401 from the snapshot request calls `waitForSignIn()` before `persist()` resolves, in every reordering that was tried. `persist()` resolves `null` without the sign-in state only when the save never reaches the server, for example when the client fails to open. A forced open failure gives exactly the CI result, and `saveStatus()` stays `pending` there, so the earlier check does not see it.
- **Error class:** A test asserts only the final flag of a chain of steps. A failure at an earlier step then looks like a wrong result of the last step and leaves no evidence of its cause.
- **Guard:** The test checks all of these together: the client opened, the snapshot request went out, the sign-in state, the status and the message. A failure prints the step that went wrong and its message. The shared 401 test checks the sign-in state, status and message in one assertion too. No repository check, because a rule cannot tell which flag ends a chain of steps.
