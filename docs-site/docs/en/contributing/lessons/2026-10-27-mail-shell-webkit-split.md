### The Mail shell browser test grew into three opaque WebKit groups

- **What happened:** In WebKit, `mail-shell.browser.test.ts` reported three tests of 68 s, 236 s, and a 300 s timeout, with no hint of the slow case. It pushed WebKit shards over their budget and blocked unrelated pull requests ([#1966](https://github.com/k2b-dev/cloud/issues/1966)).
- **Root cause:** About 110 cases ran in three child processes that only reported pass or fail. A child's output was printed only after it exited, so a timeout discarded it, and Bun prints passing cases only to a terminal. Every child built the page assets and started WebKit again. Every document parsed a 1.7 MB inline script, of which 1.6 MB was Cloud's phone navigation sheet that only `?navigation` pages use. Behavior cases also ran a second time in dark mode, which changes only colors in Mail. All of it was one file, which the runner cannot spread across shards.
- **Error class:** A browser test group whose cases are hidden from the runner grows without anyone seeing which case costs the time, until one file exceeds a shard.
- **Guard:** The suite is five test files, one per part, so the runner spreads them across shards. Each case keeps the suite's 20 s default, with no longer per-case timeouts, so a slow case fails under its own name. Each case logs its start and its time, so a file cut off by its own timeout still names the running case, and each file prints its five slowest cases. No repository-wide check, because longer per-test timeouts are an accepted convention in other browser files, and the runner already bounds each shard with `--max-minutes`.
