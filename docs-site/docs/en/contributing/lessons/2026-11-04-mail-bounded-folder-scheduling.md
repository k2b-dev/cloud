### The minute scheduler queued more folders than a mailbox's lease could serve

- **What happened:** Every minute the scheduler queued every eligible folder, up to 500. Batches of one mailbox run one at a time under its provider lease, so a mailbox with 354 folders served about 45 a minute. The rest waited and asked for the lease every few seconds. In production that was about 14,000 busy attempts every ten minutes, almost all from that one mailbox.
- **Root cause:** The scheduler planned per folder and ignored what each mailbox's lease could serve.
- **Error class:** A producer that schedules work without regard to the measured throughput of the consumer it feeds.
- **Guard:** In `remote-changes.integration.test.ts`, "a mailbox whose folder jobs still wait gets no more other folders than its lease served, in turn" requires a mailbox with waiting folder jobs to get its Inbox plus only as many other folders as its lease served in the last minute beyond those waiting. The folders take their turns in order. A mailbox with nothing waiting still gets every folder. Each process counts served folder turns per mailbox and minute in Valkey; that count is the measured throughput. At least one other folder gets in per run, so a lasting backlog cannot starve any folder. Only a run that reaches every eligible folder bounds a mailbox, so the global 500-folder paging cannot repeat the same few folders; review caught both.
