### Repeated date display work contributed to Mail folder stalls

- **What happened:** A 50-row Mail list called absolute and relative date display helpers for every newly mounted row when changing folders.
- **Root cause:** The consumed stdlib version repeatedly constructed formatters and converted display times through Dayjs timezone formatting and localized-string parsing. Stdlib 0.34.1 caches explicit-zone display formatters and formats the clock directly with Intl. Cloud adopts that release in its catalog and published package pins. Calendar arithmetic is unchanged.
- **Error class:** Repeated formatter construction and localized-string round trips in a list's display path.
- **Guard:** `packages/mail/src/frontend/_components/mail-row-date-formatting.test.ts` exercises the installed dependency with 50 and 100 pairs of row-shaped absolute/relative calls, verifies construction does not grow with page size and rejects localized-string conversion. It also checks DST and midnight. The large-mailbox browser and 20-statement SQL guards from the CSS fix cover the first-page commit of a folder switch; the browser's 250 ms per-task and 150 ms median ceilings are only regression budgets, not proof of the 50 ms goal. The browser holds the network response, omits the next-page sentinel and does not establish service-projection parity; the SQL pin excludes transport middleware.
- **Evidence and limits:** Alternating Chromium fixture A/B, 12 warm switches per side: median commit CPU 197.3 → 179.7 ms, largest commit Long Task median 102.5 → 99 ms, candidate maximum 143 ms. Commit CPU ranges overlap (158.0–259.5 vs 141.7–329.4 ms); this shared-VM result is a partial improvement, not a universal speedup guarantee. With the separate CSS change, ten warm switches per side measured 191.1 → 148.9 ms commit CPU and 94.5 → 76.5 ms largest-task median (candidate maximum 90 ms). The remaining stall exceeds 50 ms. Browser date texts matched between variants, including separate host-timezone/DST/midnight checks.

- **Dependency-bump completeness:** A stdlib bump must also update the six Grids renderer/validator provenance stamps in `document-profiles/einvoice-de.ts` and `document-profiles/financial.ts`. `packages/grids/src/document-profiles/financial.test.ts` checks every stdlib-backed profile against the installed stdlib version; it caught the stale stamps in this bump. Search the whole repository for the previous stamp before pushing.
