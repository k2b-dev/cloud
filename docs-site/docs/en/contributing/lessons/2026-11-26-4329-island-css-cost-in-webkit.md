### The island-transparent v2.css made WebKit restyle about twenty times as long

- **What happened:** On the Notebooks graph, which draws its SVG of about 300 nodes anew in every frame, WebKit's main thread saturated: taps navigated late, a keyboard walk hung and `load` never fired. On the test VM, WebKit styled and laid out such a redraw about 20 times as long with the shipped v2.css as with the plain one. Chromium paid about 2.6 times.
- **Root cause:** Two forms of the island transform (`packages/ui/scripts/v2-island-css.ts`, #4193). It wrote each rule's ways through a wrapper as one `:is()` around whole selectors, which WebKit cannot sort by the class of the subject, so it checked those rules against every new node. And it wrote `:first-child` and `:last-child` inside `:has()` as `:nth-*-child(1 of :not(:empty …))`, which makes WebKit check that `:has()` again on every change of the page. The form-row spacing rule that the bisect found was only the most visible of these rules. Without both forms, WebKit takes about three times the plain sheet's time, most of it for the child relation through a wrapper itself, and a redraw fits into a frame again.
- **Error class:** A stylesheet transform that keeps the matching right but changes what a browser engine pays for it, checked only in Chromium and only in frames, whose 16.7 ms hid any cost below them.
- **Guard:** `packages/ui/src/v2/island-css-cost.browser.test.ts` times the synchronous style and layout of 300 new nodes beside v2 sections with islands, plain against shipped sheet in the same browser, and prints the ratio. It fails above 6 in WebKit and above 3 in Chromium, thresholds set between the ratios this transform and #4193's measured under CPU limits and parallel load. A second test checks that the browser keeps every rule of the shipped sheet, because a selector list, unlike `:is()`, drops the whole rule when one selector does not parse.
