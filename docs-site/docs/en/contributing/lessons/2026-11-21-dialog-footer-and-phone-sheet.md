### A dialog's footer moved when an app showed its own error, and panel dialogs stayed centered on a phone

- **What happened:** In Spaces the task dialog grew up and down when its save failed, so the Create button moved under the pointer, against K16. On a phone the same `PanelDialog` opened as a centered dialog instead of a sheet from the bottom edge with a grip.
- **Root cause:** The footer only stayed put for the error cell of `PanelDialog.Footer error`, which measured itself around its own change. Spaces shows its error in the body, so the centered frame simply grew by half at each edge. The browser test covered only the footer's error cell, so it stayed green. `panelDialogOptions` gave a centered frame at every width; only `BottomSheet` with `bottomSheetAdaptiveOptions` became a sheet below 48rem.
- **Error class:** A layout guarantee bound to one way of changing content instead of to the frame, so every other way breaks it unnoticed.
- **Guard:** `PanelDialog.Footer` holds its place for any change of the frame's height (`holdDialogFoot`), and `flat-overlays.browser.test.ts` checks an error the app adds to the body against the viewport. The panel dialog options are adaptive like a sheet's, and the same test checks the sheet at 390 px (bottom edge, 14 px, a grip that closes it) and the centered dialog at 1024 px.
