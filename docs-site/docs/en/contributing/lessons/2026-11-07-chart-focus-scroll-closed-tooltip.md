### A chart focused before its island rendered never showed its tooltip

- **What happened:** The chart showcase browser test waited in vain for a chart's tooltip in WebKit at 1280 px (#2850), and kept failing after a first fix.
- **Root cause:** Two things took the tooltip away. First, `@k2b/ssr` islands are re-rendered, not hydrated: on a slow runner the test focused the server-rendered chart after `networkidle` but before the island's module ran, the mount cleared the island, and focus fell to the body, so the new chart never heard a focus. It hit the kinds with the largest island code (calendar, bar gauge, map, scatter, gauge); reproduced in WebKit only with a throttled Playwright container. Second, in every engine, focusing a chart partly below the fold opened its tooltip and the scroll that brought it into view closed it a frame later.
- **Error class:** Work done on server markup that the client throws away; a dismissal rule written for one input (a pointer leaving its mark) applied to another (keyboard focus) whose own side effect triggers it. A green run in one engine on a fast machine proved neither.
- **Guard:** `@k2b/ssr` moves focus to the element at the same place in the new markup when an island mounts; `packages/ssr/test/engine/island-focus.engine.test.ts` focuses server markup before the island loads and runs in the WebKit shard (red without the fix in WebKit). The inspector keeps a keyboard tooltip open on scroll in `Chart` and `ChartSnapshotView`, while `inspectChart` keeps closing on every scroll as its behaviour test requires; `packages/ui/src/content/chart-focus-scroll.browser.test.ts` covers focus below the fold, linked charts and the hover case.
