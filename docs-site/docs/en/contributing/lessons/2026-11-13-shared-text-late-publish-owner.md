### Bind late shared-text publish results to their original document

- **What happened:** A publish finishing after admission ended could replace another document's room base, snapshot and confirmed cursor when the client had switched documents.
- **Root cause:** The callback read the current connection state instead of checking its original stream and base. Writer bases compared only restore revisions, which different documents can share.
- **Error class:** A late asynchronous result mutates a newer resource owner with a coincidentally equal generation.
- **Guard:** The room captures and checks its stream, base and document; caller cancellation skips the applied callback, while an admission timeout alone preserves confirmation for an unchanged owner; writer bases check document identity on merge, commit and delivery. A real-NATS stalled-owner regression detaches the caller at the unchanged five-second admission deadline, opens another document with the same generation and verifies its snapshot and cursor remain unchanged and subsequent edits cost zero SQL. The same real-NATS harness also keeps the owner unchanged after timeout and requires its base commit and publish echo; this regression was red before distinguishing caller cancellation from the admission deadline. Unit tests reject foreign-document merges and commits and skip the callback on caller cancellation.
