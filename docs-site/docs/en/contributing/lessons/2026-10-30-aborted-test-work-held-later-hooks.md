### Work of a timed-out integration test held every later hook of the file

- **What happened:** In `integration (2)`, `Files activity with real storage > retention deletes at most 10000 rows per call` in `packages/filesv2/test/activity.integration.test.ts` timed out after 5 s on pull requests without Files changes (#2107, #2113). Every later test of the file then failed with a hook timeout, about 40 failures (#1797).
- **Root cause:** Bun stops waiting for a test that times out but cannot stop its body. Its statements kept running, or its transaction kept its locks, and the next `beforeEach` ran `TRUNCATE filesv2.activity`, which needs an exclusive lock and waited on them; everything after it queued behind. A held `ACCESS EXCLUSIVE` lock reproduces the cascade locally. What held the retention case itself in CI is still unknown: alone it takes 66 ms even under load 30, and the CI log names no statement.
- **Error class:** One slow case cascades, because shared hooks wait on database work that the aborted case left behind (as in #2118).
- **Guard:** After each test, `scripts/fixtures/test-infra.ts` ends work that outlived its test in the private databases the process owns (`ownTestDatabase()`, set by `useFreshDatabase()`, `useMigratedDatabase()` and the Filesv2 preload). It logs each statement with its blockers, so the next occurrence also names what held the timed-out case. `activity.integration.test.ts` checks the guard with a transaction that keeps the table locked and never ends: without the guard, the next test's hook times out; with it, the file passes, 99 of 99.
