### The dayHours week stopped a pixel short of its day end beside a tablet drawer in WebKit

- **What happened:** The WebKit browser test "820×1180 touch tablet with motion: the dayHours week settles Sunday's end beside the drawer" timed out after 30 seconds in some CI runs from 2026-10-22 on ([#1713](https://github.com/k2b-dev/cloud/issues/1713)). Its wait for the strip to rest never ended.
- **Root cause:** The workspace measures the open drawer with `getBoundingClientRect()`, which can return a fractional width such as 483.999969 px. The week view used that width to settle Sunday's end beside the drawer and requested `scrollTo({ left: 483.999969 })`. WebKit drops the fraction of a scroll position, so the strip rested at 483: one pixel short of the day end and of the scroll limit. A follow-up settle fell into the 450 ms guard of the first one, so the strip stayed there. Chromium rounds a fractional scroll position to the nearest pixel instead, and a measurement of 484 px or a hair more passed in WebKit too, so the test failed only sometimes.
- **Error class:** A scroll target computed from measured layout is not a whole pixel, so WebKit lands short of it and the code that expects the target never sees it reached.
- **Guard:** `snapToColumn` returns whole pixels, with unit cases for a fractional room and column width. A WebKit browser test opens a drawer of fractional width and requires the week to settle with Sunday's end beside it.
