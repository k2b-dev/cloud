### Count available human reviewers before allowing Code self-approval

- **What happened:** The Code review told a lone human admin to ask another admin, even when the other account was the emergency identity or a locked FreeIPA user.
- **Root cause:** The shared population query included the local emergency account and ignored mirrored FreeIPA locks. Excluding the emergency identity also requires checking for other reviewers so emergency authors retain their existing operator exception. Core already delegated its decisions and review permissions to that platform policy. The emergency exclusion must apply only to independent reviewers: notification recipients and event readers still include the emergency identity.
- **Error class:** Approval population differs from the identities that can provide an independent review.
- **Guard:** `versions.integration.test.ts` covers emergency authors with and without an active human `dev-admin`, ordinary authors with emergency, locked or disabled reviewers, recent sign-in, audit and version-history evidence. `code-version.integration.test.ts` covers transactional population locks, machines and role changes, including stale authority on an open request. Emergency-only notification and event-reader tests preserve those separate uses. The Code sidebar counts approvals plus open reports; its area shows both numbers from one shared `readCodeAdminCounts` snapshot, while the admin bar counts only approvals. Integration and DE/EN render guards pin the 2 = 1 + 1 breakdown for a sole author. Submit handover and DE/EN card tests use server-selected sole-approver wording. UID generation reserves `admin`; fresh emergency rows carry an explicit identity marker, so provider transitions preserve ordinary reviewer status independently of a directory UID. Ordinary identity writes share one helper that ends the marker only when provider, profile or UID changes in the same update; same-identity writes preserve it. The real `setProfile` integration guard checks a no-op before a profile change; the reviewer query uses `emergencyIdentitySql` / `isEmergencyIdentity` for the full emergency identity shape. Account sign-in restrictions and the mail exemption use `hasReservedEmergencyUid` instead, preserving reserved-name behavior for unmarked legacy accounts. Two service unit tests pin that split without infrastructure. A unit truth table covers provider, reserved UID and marker combinations. The isolated POSIX schema includes the marker column used by real provider writes; SQL-result assertions compare plain row arrays so Bun result metadata does not hide subsequent eligibility assertions. Unit and integration guards cover marker removal on provider/profile changes, stale markers on ordinary admins, an IPA `admin` switched to local and the real emergency sign-in marker. `CodeArea.render.test.tsx` and `CodeArea.browser.test.ts` check the own-author and sole-admin hints and controls. Card behavior tests await browser UI imports inside their DOM lifetime; running the next shard file also guards teardown.
