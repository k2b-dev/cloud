### A panel test posted its context before the panel could receive it

- **What happened:** The WebKit test "Chat follows only the latest host place when earlier places answer late" (`ChatPanel.browser.test.ts`) timed out in CI on a PR that did not touch Chat (#4505, shard webkit 4): `page.waitForResponse` waited 8 s for the held read of the second place (#4538). On the test VM the same test failed 5 times in 25 WebKit runs.
- **Root cause:** The test posts `cloud.panel.context` messages to the panel frame itself, and it started as soon as the fixture marked the frame ready. The panel installs its context receiver in `PanelRuntime` a moment later and then sets `data-cloud-panel-ready`, the mark the shell's own controller waits for. A message posted before that is lost, so the panel never asked for the place it named, and the wait for its response could not end.
- **Error class:** A browser test that plays the shell's part (posting panel context) without waiting for the mark the shell waits for; and a wait for a page event about a request the page may never send or may cancel.
- **Guard:** The three tests that post panel context wait for `html[data-cloud-panel-ready]` first. The held read records in its own route when it arrives and when its answer is handed over (`route.fetch` and `route.fulfill`) or dropped, and the test waits for those records with a named 8 s deadline instead of `waitForResponse`. Red before: 5 of 25 WebKit runs; after: 30 of 30 for this test, and the whole file repeated in WebKit and Chromium without a failure.
