### Gustav could not create a chat because its review left the turn behind

- **What happened:** Every `core.ai.chat.create` from a Gustav turn failed with `source_unavailable` (409), in the browser and in the CLI. Code without Gustav created chats. Core logged "Nested Query exchange unavailable" many times, without a reason.
- **Root cause:** Before an Action runs, Gustav asks the app for a live review. The AI executor called `reviewAiCapability` without the turn ID, so the review was dispatched with the Assistant origin but without `assistantTurn`. Without a turn, a proof or a mandate, the dispatcher builds no nested-invocation lease. The review of `ai.chat.create` checks the source turn through that lease, found none, and refused. The run itself carried the turn, so tests of the run alone stayed green. The logged warnings came from a second case: resource and origin readers dispatch with the Assistant origin, a session proof and no turn. The lease schema refuses that combination, and the bare `catch {}` hid the `ZodError`.
- **Error class:** One step of an operation (review, check, run) is called with less context than its siblings, and the target cannot tell a missing source from an unavailable one. A swallowed error hides which of the two happened.
- **Guard:** The executor integration test "resumed capability approval binds the live review" requires the review to carry the turn's conversation and turn ID; it fails on the old code. `ai-chat-create.integration.test.ts` runs a Gustav turn's review and run through the real dispatcher, the stored lease and Core's action: without the turn the review is refused, with it the chat exists. The dispatcher builds a lease only when the origin and the turn agree (`nestedLeaseTurnMatches`, shared with the lease schema) and names the mismatch in a debug line. A failed lease setup logs its error class and code.
