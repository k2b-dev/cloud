### A box whose only content goes away falls back to its empty sentence

- **What happened:** The P5 tour of the Gustav preview set a one-off alarm in a chat that had no results, sources, project, Skills or memories. Before the alarm rang, the box "In this chat" showed the alarm. When it had rung, the box fell back to "Results, sources, and automations of this chat appear here." On a phone, the chip beside "Waiting for you" showed only the alarm sign and "2", without the word "Alarms".
- **Root cause:** The box counted as empty from the current snapshot alone. #3756 kept it when the chat had context, but this chat's only content was the alarm, and a one-off alarm leaves the list when it has rung. The narrow rule of the row hid the word in every chip, including the alarm chip, which the alarm concept shows with its word.
- **Error class:** A state computed from the latest data alone makes a surface jump back to its empty state under the person's eyes when the last item goes; a narrow rule written for one chip catches a later chip with a different contract.
- **Guard:** `AssistantChatContextBox.behavior.test.tsx` swaps the snapshot of the same chat from "one alarm" to "nothing" and expects the box to keep its lines; a reload and another chat still start empty. `chat-context-box.test.ts` covers the `filled` input. `wakeup-dock.browser.test.ts` runs the shared row at 390 px and expects the word in the alarm chip without moving the row. `wakeup-dock.behavior.test.tsx` opens and closes the list with a click on the chip.
