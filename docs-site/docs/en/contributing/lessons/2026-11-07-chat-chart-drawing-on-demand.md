### Keep optional drawing loads inside the chart boundary

- **What happened:** Adding chart kinds exceeded the Assistant PWA and workspace JavaScript budgets, even in chats without charts. Deferring the entire island to retain its server drawing also delayed the composer and unrelated controls.
- **Root cause:** Shared presentation imports pulled in the renderer catalog. Waiting for that optional module at the island mount crossed the boundary between a drawing and the surrounding chat.
- **Error class:** Optional presentation code blocked unrelated interaction and risked discarding input typed before the delayed mount.
- **Guard:** Unchanged island budgets and a static-graph check exclude the registry and map data. Chart-local wrappers claim their detached server subtree synchronously; unclaimed subtrees expire in a microtask. Short stable data fingerprints avoid repeating chart JSON in the server markup. The island mounts immediately. Browser tests require the same SVG node and bytes, readable named drawings with a polite loading status and visibly disabled controls, exact desktop/phone frames, a usable composer and sibling controls through success and localized load failure, and cancellation after chart removal. The drawing module attaches the normal inspector. The handoff uses the owning window’s registry and element constructors, including successive DOM test windows. Loading status portals use `display: contents` so their wrapper cannot add a grid row. History tests wait for the mounted island while the drawing response remains pending. Stat sparklines retain byte-for-byte parity with Chart.
