### A mail server that dropped every connection was knocked on every minute while its syncs reported success

- **What happened:** A mail server stopped answering connection attempts from the installation, probably because it blocked the installation's address. The affected mailboxes received no new mail for hours. Each folder sync's first attempt timed out after 15 seconds, and its retry settled as a successful run 30 to 250 ms later. Push reconnected about every minute, and after each failed connection it also queued a rediscovery. In one day, that made 1,466 rediscovery runs that tried the server again.
- **Root cause:** The provider breaker's longest window was one minute. While it was open, a folder sync or rediscovery got the same "busy" answer as for routine lease contention. It resubmitted itself and settled as done. IMAP push neither waited for the breaker nor opened it. Each failed connection sent a `disconnected` hint, and that hint queued a folder sync and a rediscovery because the binding's last verification was overdue. Rediscovery also opened two IMAP connections at once for verification and folder discovery.
- **Error class:** A retry path that reports "deferred" in the same way as "done", and a backoff with a cap below the cadence of the work it guards.
- **Guard:** `imap-push-runtime.test.ts` ("IMAP push against a mail server that drops connection attempts") runs push on a virtual clock against a server that never answers. It requires growing intervals up to 15 minutes, no rediscovery and no folder sync until the server answers again, and a reset when push reaches the server. Before the fix, the same run queued 52 rediscoveries in one hour. `sync-recovery.integration.test.ts` ("a folder job that finds the mail server unreachable neither counts as done nor retries…") requires the `unreachable` outcome, a degraded folder, exactly one SQL statement, no scheduled check while the window is open, and an immediate try after a manual sync. `provider-lease-fairness.integration.test.ts` pins the window growth up to 15 minutes. `network-security.test.ts` checks that plain and TLS sockets reach the second vetted address when the first one drops connection attempts.
