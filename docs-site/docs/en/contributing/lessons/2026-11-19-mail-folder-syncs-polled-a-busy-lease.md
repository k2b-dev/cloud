### Folder syncs polled a busy mailbox lease and wasted most of their turns

- **What happened:** In production, folder syncs logged 10,000 to 14,000 `busy` turns per ten minutes against 245 to 330 committed batches. About 97 % of the turns, roughly 20 per second, found the mailbox's provider lease held and achieved nothing. The jobs, the lease line and the queue carried that load all the time.
- **Root cause:** A folder job that found the lease held resubmitted itself after at most four seconds. Every folder job of a busy mailbox therefore asked again and again until its turn came, also while the holder waited for a 15-second connection timeout.
- **Error class:** Polling a shared lock from a queue instead of letting its release wake the next waiter.
- **Guard:** `provider-lease-fairness.integration.test.ts` runs 30 folder jobs on a test clock while a command holds the lease for a minute. Each job asks once and parks, where polling asked 967 times. After the release, each release wakes the next job, which gets the lease at once, with no busy turn. `sync-recovery.integration.test.ts` uses `meterSql` to require that a parking turn and the wake run no database statement, and that a parked push keeps its rank and input for the folder's next job. The existing fairness tests now run through parking and waking.
