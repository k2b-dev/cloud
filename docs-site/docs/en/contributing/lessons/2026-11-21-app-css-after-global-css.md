### An app's own utility lost to a shared utility on the same element

- **What happened:** On Warenfluss pages, a shared `m-0` beat the app's own `-mt-1` on the same element, so the app had to rework six places (#3921).
- **Root cause:** The document linked `/public/<id>/app.css` before Core's `global.css`. Both stylesheets put their Tailwind utilities in `@layer utilities` at equal specificity, so the later shared sheet won. Moving the app sheet after the shared one exposed two more cases. An app sheet without Cloud's theme compiles `transition` with `0s` and `ease`, which would have ended app transitions at once. Shared markup in Cloud paired a plain utility with a breakpoint variant (`grid-cols-1 sm:grid-cols-2`), and the Tools app sheet repeats the plain one.
- **Error class:** Two stylesheets put the same utilities in one cascade layer. Then their link order decides each conflict, so one sheet's rules silently cancel the other's on the same property.
- **Guard:** `packages/cloud/src/_internal/define-app.css-order.browser.test.ts` renders the real app document and checks that an app utility beats a shared one on the same property and that an app `transition` keeps the shared 150 ms. `define-app.pwa-head.test.ts` pins the link order. `packages/cloud/scripts/tailwind.test.ts` covers the build's transition defaults. UI-28 (`breakpoint-display`) keeps shared responsive displays scoped on both sides. For other properties and `dark:`, the guard is pending in #3924.
