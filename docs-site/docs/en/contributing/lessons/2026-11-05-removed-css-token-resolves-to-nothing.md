### A removed CSS token left Remove black and the access dialog short of its mockup

- **What happened:** "Remove" in the access dialog's level menu used `--k2b-danger`, which `@k2b/ui` no longer defines, so it was not red. A repository scan found 13 more uses of tokens that nothing defines, among them `--ui-accent` for Mail's options dot and the Spaces fallback color, `--ui-bg` for the Grids scanner, `--k2b-accent` for a sidebar focus ring, and `--k2b-text-dimmed` for editor line numbers. The same checklist found the dialog without "Saving …", without the number of signed-in people, without e-mail lines and without General while loading.
- **Root cause:** `var()` of an undefined custom property is valid CSS and silently resolves to the inherited or initial value, so neither the build nor a test noticed when tokens were renamed. A utility color class on a `@k2b/ui` button could not have worked either, because button styles sit outside the utility layer.
- **Error class:** A style references a design token by a name that no longer exists, and nothing fails.
- **Guard:** The `css-variables` repository rule fails on every `var(--k2b-*)` or `var(--ui-*)` without a fallback whose name no stylesheet declares and no code sets. A destructive text button uses `data-danger="true"`, and `AccessDialog.browser.test.ts` checks that Remove has the danger ink and covers the loading, saving, public and level-menu states of mockup v31.
