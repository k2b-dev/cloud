### Order only rules that can compete for the same effect

- **What happened:** Adding frozen Mail workflow ordering left guided automations waiting behind unrelated rules and bypassed their existing moved-message checks. Status, hydration, and retry integration suites regressed.
- **Root cause:** Every earlier event was treated as a competitor for every class, including nonmatching header scopes and plans without that effect. The ordering change also expanded legacy skip/no-op outputs. Advancing revisions without preserving a contiguous effect prefix broke trigger hydration; a summary no-op could also accept a person's newer revision. Verification omitted Mail's integration preload, hiding provider behavior behind missing Sync errors.
- **Error class:** A new coordination fence broadens dependencies and replaces existing correctness guards.
- **Guard:** `workflow-effect-order.integration.test.ts` checks pinned versions and immutable headers, independent effect classes, unresolved body conditions, UUID ordering, effect-then-hydration, reference allocation, and summary no-ops after a person's change. The unchanged status/hydration/revision assertions in `incoming-automations.integration.test.ts` protect shipped behavior. Mail integration commands must include both `scripts/fixtures/test-infra.ts` and `packages/mail/test/integration-preload.ts`; the package integration runner supplies both.
