### Grouped class selectors contributed to expensive Mail folder commits

- **What happened:** Switching a large synthetic mailbox's folder retained the old list while loading, then blocked the browser when committing 50 rows. The list was paginated; neither a page reload nor a new live connection caused the client stalls.
- **Root cause:** One contributing cause was that the UI stylesheet grouped individual classes inside `:is()` and compatibility `any()` selectors. Distributing only equal-specificity, top-level class alternatives in the UI build reduced median style CPU from 86.5 to 57.3 ms and commit CPU from 192.0 to 162.1 ms in Chromium, ten warm switches per side. About 162 ms of commit CPU remains. This is a partial improvement: the candidate's largest commit Long Task had an 84.5 ms median and a 93 ms maximum (baseline 95.5 ms median, 111 ms maximum), above the 50 ms goal. The browser target and other compatibility transforms remain unchanged.
- **Error class:** A CSS build hides classes from efficient selector indexing in a large interactive surface.
- **Guard:** `packages/ui/scripts/index-class-groups.test.ts` checks specificity, nesting and whitespace, verifies the actual shipped stylesheet, and rebundles the output with Bun's browser target. The large-mailbox Chromium test retains the pending list and its bounds, checks one list fetch, stable sidebar root, URL/back/reload, bounded DOM and a 250 ms warm Long Task ceiling and 150 ms median ceiling (93 ms A/B maximum; three later full guards reached 133, 180 and 173 ms at load below 32, so the maximum allows about 40% headroom above 180 ms; the baseline can also pass, so these are regression budgets and not proof of improvement or meeting 50 ms). The fixture omits automatic next-page loading and does not establish service-projection parity. The uncompressed UI stylesheet grows from 1,314,677 to 1,361,261 bytes because equivalent compatibility rules are retained. The service integration test pins folder resolution and the complete authorized 50-row projection to 20 SQL statements.
