### A message sent right after Quote showed nothing until the quote's code had loaded, and went out without a quote that could not load

- **What happened:** Since the fix for #3702, a send right after "Quote" waited for the quote's code before it created the pending message row. The field was already empty, and nothing showed until the chunk arrived: about 800 ms in a probe, seconds on a slow network, so the message looked lost (#3999). When the chunk failed to load, the message went out without its quote, and only a general reload notice said that something was missing.
- **Root cause:** `send` in `packages/chat/src/frontend/ChatWorkspace.island.tsx` awaited `quotesOnTheWay` before it called `outbox.send`, so the visible row and the post waited together. `importOnDemand` resolves `undefined` when code cannot load, and the quote chain then ended as if there were no quote.
- **Error class:** An await that only the network request needs sits in front of the optimistic UI, and a failed optional load is treated like no input, so part of what the person sent is lost without a visible state.
- **Guard:** `packages/chat/src/frontend/ChatQuotes.browser.test.ts` holds back the `chat-quote-selection` chunk and checks that the pending row shows before anything is posted; with a chunk that fails, it checks that the message stays "not sent" with "The quote could not load" and posts nothing until "Retry" (with the quote) or "Send without quote". `chat-sends.test.ts` covers hold, fail, retry and release.
