### Countdown updates briefly removed the privacy blur

- **What happened:** The shared workstation warning made covered content flicker on every countdown tick. Its main action and other global Cloud dialogs could also turn plum after focus in an AI area.
- **Root cause:** The privacy observer treated the warning's text update as a reason to rebuild coverage. Reconciliation removed every cover and `inert` attribute, then measured the hint's position before restoring them. That layout read committed the unblurred style and restarted the content's filter and opacity transitions. The dialog itself stayed mounted and its backdrop filter stayed at 8 px. Separately, the global warning inherited the focused AI area's primary palette.
- **Error class:** Rebuilding persistent presentation state around a synchronous layout read; inheriting a task's presentation for an unrelated global operation.
- **Guard:** `shared-workstation.browser.test.ts` runs four controlled countdown ticks with real CSS motion and checks stable coverage, inertness, filters, dialog identity, backdrop blur, and zero animation or transition starts. It fails without the coverage fix. The same file checks blue warning actions at desktop and phone widths in both themes. `dialog-primary.browser.test.ts` checks explicit blue inside an AI document, ordinary inherited children, explicit AI children, and palette restoration on return. `dialog-tone.browser.test.ts` checks ordinary primary actions in every shared dialog shape and tone. Global Cloud search, resource picking, file saving, and app menus choose blue explicitly.
