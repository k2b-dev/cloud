### A prompt that loaded its code first opened with the context of the moment the code arrived

- **What happened:** A form prompt, a typed confirmation, or a phone sheet asked for before its code had loaded could open with the default palette in an AI-coloured area, open over a page that `@k2b/ssr/nav` had navigated to in the meantime, and return focus to whatever was focused when the code arrived (#3782).
- **Root cause:** `dialogCore.open` reads the palette scope, the island-disposal count and the opener when it is called. `prompts.form`, `confirmPrompt` with a `confirmationPhrase` and the phone sheet in `openPrompt` called it only after awaiting their chunk, so all three values came from a later moment. WebKit does not focus a clicked button, so the focus at arrival is often somewhere else.
- **Error class:** A function that reads ambient state (focus, palette, page generation) is called after an `await`, so it reads the state of a later moment than the call that asked for it.
- **Guard:** `captureDialogOpen()` in `packages/ui/src/feedback/dialog-core.ts` reads the context synchronously at the call and opens through `dialogCore.open` with it later; a navigation in between resolves `undefined` without opening. `packages/ui/test/prompt-call-context.behavior.test.ts` changes the focus and disposes islands while the form, phrase field and sheet chunks are pending, and fails on the old code. No repository check, because a rule cannot tell which reads after an `await` depend on ambient state.
