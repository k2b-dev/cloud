### WebKit refused one Ed25519 key generation in a hundred, and the one-time key dialog never opened

- **What happened:** `keys: the private key shows once, and closing it unsaved asks first` timed out in WebKit CI jobs waiting for the one-time key dialog after **Create** (#2286). It passed in Chromium and in most WebKit runs.
- **Root cause:** Playwright's WebKit on Linux rejects `crypto.subtle.generateKey("Ed25519", …)` with an `OperationError` about once in a hundred calls: 21, 29 and 32 of 3,000 generations in WebKit 27.2 (Playwright 1.64.1), none of 6,000 in Chromium. `generateAppKeyPair()` passed the error on, so the create dialog showed a registration failure instead of the key. The browser check behind **Create key** made the same call and reported such a refusal as "no Ed25519", which made the test return early without creating a key.
- **Error class:** A test or a feature treats one result of a randomized platform operation as the engine's capability, so a rare engine refusal looks like a timing flake or a missing feature.
- **Guard:** `generateAppKeyPair()` draws a new pair after an `OperationError`, up to three attempts, and the browser check counts that error as support. `app-key.test.ts` refuses generations through a spy, and `page.browser.test.ts` refuses the browser check and the first generation in both engines and still expects the one-time key dialog. The existing test no longer returns early when the button is still disabled; it waits until the button is enabled.
