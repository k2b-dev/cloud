### A long-lived branch merges cleanly and still breaks the other side

- **What happened:** `feat/capability-blocks` (34 commits, six days old) merged onto `feat/code` with eighteen textual conflicts, and every package typechecked afterwards. Integration suites against the merge still found seven defects: a JSONB subtraction that bound to a call id and failed every Code version list, pending action arguments parsed twice, the choice history read twice per chat stream admission and once per live message (15 instead of 13 statements), approval edits that could not reach shared drafts in the frozen room, a NUL in an approval sentence, response schemas that JSON Schema could not project, and tests on both sides that encoded the other side's old contract.
- **Root cause:** Each branch was green only against its own base. Behaviour that lives in SQL fragments, statement budgets, storage forms and published schemas is invisible to the type checker, and the branch had never run the other side's integration suites.
- **Error class:** Semantic merge clash between long-lived branches.
- **Guard:** Before opening a pull request that merges a long-lived branch, run every integration file that imports a changed path (`git grep -l` over `*.integration.test.ts`) against isolated `_test` containers, plus the SQL budget tests of the hot paths it touches (`scripts/fixtures/sql-meter.ts`). The admission budget test in `packages/cloud/src/ai/routes.integration.test.ts` and the new projection checks in `packages/cloud/src/_internal/capability-reviews.test.ts` caught the two quiet regressions here.
