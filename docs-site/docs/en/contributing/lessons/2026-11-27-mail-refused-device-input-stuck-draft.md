### A shared draft stayed read-only after every reload

- **What happened:** In some Mail replies, typing was impossible. The reply box said "This draft changed. Keep your text and reopen the draft." Reloading or "Retry" showed the same state again, every time.
- **Root cause:** A remembered device sends its stored unsent input again on every open, against the base cursor it stored. Once Mail pruned the log prefix behind that base, the room refused the input with `RESYNC_REQUIRED`. The draft itself was still open at the same generation, so the client's `recover()` saw nothing to recover and only reported "draft changed". The bytes stayed in IndexedDB, and the next open sent them again.
- **Error class:** A refusal that the client treats as a change of the server's state. A retry or reload then repeats the refused input forever, because nothing moves it out of the device's storage.
- **Guard:** `mail-draft-document.browser.test.ts` ("input the open draft refuses …") refuses the input like the room does, in real IndexedDB. It requires exactly one recovery request, an emptied device store and an editable draft after reload. `draft-document-socket.integration.test.ts` ("device input whose base the log pruned …") prunes the base of stored device input. It requires the refusal on every join while the draft stays open at its generation. Rest must then keep the input as the open reply's only recovery copy, idempotently, and a fresh join must take new edits.
