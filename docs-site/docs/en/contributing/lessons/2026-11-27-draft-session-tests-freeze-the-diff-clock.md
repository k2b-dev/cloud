### Mail draft session tests failed under CI load with "Draft could not be saved" or "Missing local publication"

- **What happened:** In CI, the Mail draft session behavior tests for an expired sign-in (#4394) and for transport echoes (#4312) failed now and then. `prepareSignIn` refused with "Draft could not be saved", or the test found no published update. On an idle machine the same tests passed hundreds of times.
- **Root cause:** These tests change the draft body through `setCurrent`. In a shared draft, the session hands that change to `client.edit`, which bounds the body diff by one 60 Hz frame of wall-clock time (`diffChars` with `timeout`). On a loaded runner, the thread could stall for longer than that frame in the middle of a short diff. The client then rejected the edit as over budget: it published nothing, and `prepareSignIn` correctly refused to reload. The order of the socket close and the device save did not matter. The product handles the refusal: `MailComposer` catches it and shows a toast.
- **Error class:** A test result depends on a wall-clock budget, so CPU load on the runner decides the outcome. Here the class is a test edit through the wall-clock-bounded diff: any test that changes a shared draft body through `client.edit` or `setCurrent` with the real clock.
- **Guard:** `mail-draft-session.behavior.test.tsx` freezes the clock in `beforeEach`. The three affected tests make their edit through `afterSchedulerStall`, which stalls the thread for more than one frame after the first clock read. Without the frozen clock they fail every time, with the same errors as in CI. `mail-draft-document.browser.test.ts` freezes each page clock at load and stalls every clock read while it adopts a rejected proposal; with the real clock that step fails every time. The MailComposer behavior tests make no body edit through this diff: with a budget that always runs out, they still pass.
