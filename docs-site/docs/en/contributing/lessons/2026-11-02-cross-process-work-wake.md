### Idle dispatchers poll too often while wake signals stay inside one process

- **What happened:** Idle outboxes, workflow workers, and Core event delivery queried Postgres every second. Outbox notifications woke only their own process. New commit hints also submitted jobs during Chat service tests that polluted a later worker test.
- **Root cause:** A one-second recovery timer also served as normal work discovery. Core discarded hints received during an active pass and tied minute maintenance to pass count. Tests drove delivery explicitly but also allowed commit hooks to publish real jobs. Distributed hints echoed back to processes that had already woken locally.
- **Error class:** Polling replaces distributed wake signals; concurrent hints are lost; test background work escapes its scope; local wake signals echo through the broker; maintenance depends on traffic volume.
- **Guard:** `idle-workers.test.ts` advances a frozen minute and counts twelve safety scans per dispatcher, with separate workflow slot counts; it also checks the exact retry boundary. `outbox.integration.test.ts` checks an independent writer, ignored local echoes, retry recovery after restart, and draining. Chat service tests isolate incidental publishing, while the worker test exercises real delayed delivery with unchanged message assertions. Workflow transport tests check ignored own echoes and remote wake signals. `app-events/runtime.test.ts` checks coalescing, backlog draining, shutdown, and failure recovery.
