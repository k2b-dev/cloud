### A phone sheet waited for its background trigger's hover

- **What happened:** The Mail remote-images rule test failed while opening its phone sheet, blocking an unrelated Chat PR (#3351).
- **Root cause:** The test used a document-wide animation wait after tapping the trigger. Touch hover on that background control could start a color transition while the sheet settled. CI recorded that exact hovered trigger before any rule was revoked; the adjacent phone-sheet test already scoped its wait to the sheet.
- **Error class:** Waiting for unrelated background motion instead of the surface whose state the test reads.
- **Guard:** The rule test now waits only for document-timeline animations inside the opened surface. After revoking both rules, it moves the pointer away and waits for the restored trigger's unhovered original color, closed menu, and returned focus. This guards against the restored trigger staying hovered, open, or unfocused once the pointer leaves. The original focused case passed locally, so the exact CI overlap was not forced; the scoped wait removes the recorded trigger from its animation set while preserving every rule assertion and the existing timeout. The convention is to scope the wait to the surface being read; `settled()` exposes accidental background motion through its hovered-target diagnostic. The `animation-settle` and `settle-reads` checks validate the timeline filter and waiting before style reads, but do not enforce that scope.
