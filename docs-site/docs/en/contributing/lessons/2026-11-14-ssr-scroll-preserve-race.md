### A reload test consumed another test's navigation response

- **What happened:** A replace swap sometimes kept the old page in the scroll-preserve browser test (#3287).
- **Root cause:** The dev-reload fixture evaluated the document-lifetime client on the shared window, then restored globals without removing its lifecycle listeners. A later test's `pageshow` revived the client. Its retry ping could consume a one-shot navigation response while an island import yielded; the subsequent swap fell back to document navigation instead of replacing the column. The nav-swap and scroll-preserve implementation was not responsible.
- **Error class:** A document-lifetime singleton escaped its test fixture and interfered with a later test's mocked I/O.
- **Guard:** `client-reload.browser.test.ts` now suspends the client, removes the listeners installed during evaluation, and releases pending leadership before restoring globals. After teardown, the same test dispatches `pageshow`, triggers any revived stream's error, and advances the existing 300 ms retry with fake timers. It asserts that no connection or navigation fetch occurs. This guard failed with one unexpected fetch under the original cleanup and passes with the fix. The precise CI scheduling window was not reproduced locally; the guard deterministically exercises the cross-file interference without a longer timeout, a retry, or Cloud dependencies.
