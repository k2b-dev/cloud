### Keep step text and lifecycle under one owner

- **What happened:** Step revisions and output pressure could change retained step text or order, while exhausted handle storage interrupted author code.
- **Root cause:** Revision snapshots were treated as new text, the window evicted entries solely by age, and capture and replay accounted different representations.
- **Error class:** Mutable metadata mixed with lifecycle updates, mismatched representation budgets and inconsistent overload behavior. Eager wire accounting also assumed Web Encoding globals, and an immutable console conflicted with a runtime that installs its own forwarding methods.
- **Guard:** Focused redaction, console, window and output integration tests pin one-time text admission, monotone lifecycle, terminal immutability, soft limits, retained step order, canonical byte reservations across Runner and Core, inactive IDs, chronological completion text, separate automatic reasons, actual tier configuration, final settlement, replay and zero SQL per update. Script VM and shipped-loader tests cover startup without `TextEncoder`, writable runtime console methods and preserved Assistant messages; UTF-8 reservation cases cover JSON escapes and surrogate pairs.
