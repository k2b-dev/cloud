### A venue's public page grew with every saved section and menu item

- **What happened:** Venue admins, API keys, and `cld venue sections create` could save any number of public sections and menu items. The guest page renders all of them in one SSR response and repeats each in the island's serialized props, so its HTML grew without bound.
- **Root cause:** The section services validated each section's shape but never counted what the Venue already stored, and the public read listed every enabled section.
- **Error class:** A public page that renders every stored row of a collection that users grow, with a size limit nowhere on the write or the read path.
- **Guard:** `MAX_PUBLIC_SECTIONS` and `MAX_PUBLIC_MENU_ITEMS` in `packages/venue/src/contracts.ts`, derived from `PUBLIC_PAGE_HTML_BUDGET_BYTES` with measured sizes. The section services check them under a lock on the Venue row and answer 422 with `PUBLIC_SECTION_LIMIT` or `MENU_ITEM_LIMIT`. `public-section-limits.integration.test.ts` fills a Venue to both limits, checks that the guest page stays within the budget, that one more section or item is refused and stores nothing, and that two parallel saves never pass the limit together.
