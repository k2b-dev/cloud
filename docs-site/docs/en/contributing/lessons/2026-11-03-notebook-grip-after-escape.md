### A table menu closed before its toggle event left every other grip hidden

- **What happened:** The Notebook browser test "right-click shows the whole menu and each grip its row's or column's part" timed out in Chromium on several unrelated pull requests and in the merge queue ([#2520](https://github.com/k2b-dev/cloud/issues/2520)). After the row grip's menu closed with Escape, the column grip stayed hidden, although it had its hover and current-cell marks.
- **Root cause:** A popover queues its `toggle` event as a task. When a menu closes before its opening event runs, Chromium sends one coalesced event from "closed" to "closed". `Dropdown` took `oldState` as the answer to "was it open?", so it never called `onClose`. The text editor never reset the grip's scope, the row grip kept `data-open`, and the `:has(.k2b-ste-grip[data-open])` rule hid every other grip until the next menu. The CI failures show exactly this state; most likely, input on a busy runner overtook the opening event there.
- **Error class:** Deriving component state from a coalesced asynchronous browser event (`ToggleEvent.oldState`) instead of the state the component set itself.
- **Guard:** `Dropdown` remembers that it showed the popover and reports the close even for a "closed" to "closed" event. `text-editor-component.browser.test.ts` opens a row grip's menu and presses Escape in the same task, then checks that no grip or row stays marked and that the grips of the same and the next cell show and open their menu. The test fails without the fix.
