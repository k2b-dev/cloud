### Lifecycle marker expectations must survive covered pruning

- **What happened:** Completing a sent draft's shared-document close could fail with `ConflictError: expectedAfter no longer matches`. A subsequent retry could clear the pending intent without completing its close notification.
- **Root cause:** Document admission serializes appends and lifecycle changes, but snapshot-covered prefix pruning uses a separate lock. A snapshot commit schedules pruning, which can remove the tenant head after close captures it and before the broker checks its append expectation. Mail's retry catch treated every conflict as an invalid token, including a definitely rejected notification for the current token.
- **Error class:** Prunable optimistic-concurrency tokens mistaken for lifecycle ownership.
- **Guard:** The Mail retention integration test forces the real pruner between close-head capture and notification, then checks closed authority, a completed intent and unchanged body/revision. A second service test rejects close publication twice and requires a pending intent with a visible error until a later retry completes it. Shared-text lifecycle unit tests cover pruned heads, owner replacement and retained-head conflicts. The library retries only a definite conflict against a vanished head, once, while its authority revision still matches; other failures stay visible. No normal-path SQL statements are added.
