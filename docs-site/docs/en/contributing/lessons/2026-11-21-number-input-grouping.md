### A number input changed amounts without an error

- **What happened:** `NumberInput` turned a typed or pasted `2.977,17` into `2.97` in German, `2,977.17` into `2.97` in English and `1.234.567,89` into `1.23`. With `allowNegative={false}`, it turned a pasted `-5` into `5`. With `step={0.01}`, it committed `1.005` as `1.00`. The field showed no error, and the parent received the wrong value. Core admin AI prices and budgets with `step={0.01}` were among the affected fields (#3897).
- **Root cause:** The input filter read the first `.` or `,` as the decimal separator, dropped every later mark and every minus it did not expect, and cut the fraction to `decimalPlaces` while typing. It did not know the locale's grouping mark, so a grouping mark moved the decimal point. Commit rounding snapped the binary float (`1.005` is `1.00499…`), so halves could round down.
- **Error class:** An input normalizer that discards characters it cannot place or rounds an inexact float, which silently changes a value instead of refusing the text or rounding the decimal the person typed.
- **Guard:** `packages/ui/test/number-input-grouping.behavior.test.ts` covers grouped German and English amounts, key-by-key typing, a paste with a currency sign, refused text that keeps its text, shows an error and commits nothing, a trailing minus, a minus without negatives, Enter in a form, and the classic half cases (`1.005`, `2.675`, `1.015`, `0.125`, `1.234,565`). `NumberInput` now reads the whole text with the locale's marks, refuses text it cannot read, and rounds the number's shortest decimal form with `Intl.NumberFormat` and exact integer step snapping. The `island-bundles` budget of the Assistant island held the fix to its size.
