### A loading iframe left the panel controller half installed

- **What happened:** Two consent-menu browser tests failed intermittently in the `ssr-ai` CI part on the Code integration head. The menu could remain enabled during a save, or withdrawing consent could time out. Running the panel file alone initially passed, suggesting a compiler plugin leaking from another test.
- **Root cause:** During navigation, an iframe can expose a `contentDocument` whose `documentElement` is still `null`. The controller read `documentElement.dataset` after registering its listeners, then threw before mounting the menu and recording its installation. A subsequent installation retained those listeners and added another controller. This produced duplicate consent writes, revision conflicts, and a menu observing a different controller. The browser stack identified the null-root access. Passing and failing runs produced identical browser bundles and equivalent server HTML, and repeating the panel file alone reproduced the failures; the compiler-leak hypothesis did not explain this case. The same unsafe accesses also existed on `main`. The local baseline also hit a separate setup timeout: the View-Block fragment fixture discovered and built 330 islands across every package, although it built its browser assets independently.
- **Error class:** A browser installer assumes a navigating iframe's document already has a root and fails after acquiring resources but before recording its installation. A separate, previously demonstrated error class is a test changing the process-wide Solid compiler, silently changing how neighbouring tests compile components (#3626).
- **Guard:** Both readiness probes tolerate a missing document root. The browser regression `a panel frame without a document root does not leave a partially installed controller` exposes a rootless document while the lazy controller installs, then verifies menu mounting, consent changes, and exactly one write per action. It fails deterministically before the fix. The fragment fixture now uses `componentRoots: []` and keeps its original setup timeout. The independent `test-solid-plugins` repository rule requires tests and test helpers to register their SSR compiler through `packages/ui/test/ssr-test-plugin.ts`; only the designated DOM preload and the standalone app-plugin subprocess fixture register directly. Its counter-tests reject the original panel-test registration, the former raw SSR preload, and the #3626 render-test pattern. DOM suites cannot import the SSR helper or SSR preload. Build-local plugins and subprocess source strings remain local. Existing registrations use the shared helper, preserving their configuration; the pull request lists every migrated file. No compiler rule can catch the transient iframe root: the browser regression guards the confirmed cause.
