### A render test that registers the SSR compiler wrote JSX of its own

- **What happened:** Splitting `@k2b/ui layout-content` into two suites made `@k2b/ui content` fail in CI before its first test: `src/content/content-contract.render.test.tsx` stopped with `Export named 'jsxDEV' not found in module …/solid-js/dist/solid.js`.
- **Root cause:** The file calls `registerSsrTestPlugin` at its top and also holds JSX of its own. Bun compiles a file's own JSX when it loads it, before the registration runs, and since Bun 1.4.3 Solid has no runtime for that JSX. In the old suite a layout test ran first and had registered the compiler already. As the first file of its own process, the content test failed. Bun 1.4.2 on a workstation still loads such a file, so only CI showed the failure.
- **Error class:** A test file that works only because an earlier file of the same process set up its compiler. This is the class of [Bun 1.4.3 no longer loads a .tsx file without the Solid transform](2026-11-01-bun-untransformed-tsx-jsx-runtime.md), hidden by the order of files.
- **Guard:** The `test-solid-plugins` rule now finds every file that calls `registerSsrTestPlugin` and holds JSX of its own. Such a file writes `createComponent`, or keeps its JSX in the modules it imports after the registration. The one file left, the Chat panel's browser fixture, is a named exception until #4456 fixes it.
