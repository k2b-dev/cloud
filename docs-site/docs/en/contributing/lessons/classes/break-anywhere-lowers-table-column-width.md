| Break-anywhere lowers table column width | `overflow-wrap: anywhere` (or `word-break: break-all`) on table cells lowers each column’s min-content width to one character, so a short column next to a long one breaks `Nr.` or `100` inside the token. Without a wrap rule, a long URL widens the table past the reader instead. | Tests: the [#785](https://github.com/k2b-dev/cloud/pull/785) UI tests (Notebooks `book-tables.browser.test.ts` and Cloud `table-rendering.test.ts`), Mail `compose-renderer.test.ts`, and the Mail `MailMessageBody.browser.test.ts` / `MailComposerEditor.browser.test.ts` table tests in Chromium and WebKit; Cloud PDF `markdown.test.ts` and `markdown.integration.test.ts`, and Notebooks `note-pdf.integration.test.ts`. Convention: cells use `break-word`; only links and code inside screen cells break anywhere, and the reader lets a whole table break anywhere only when keeping words whole would make it wider. PDF presets and documents without a preset use `break-word` on cells: words of up to 20 characters stay whole; a longer run gets a break opportunity every 10 characters, including links and code, because print cannot scroll and runs no script. |
