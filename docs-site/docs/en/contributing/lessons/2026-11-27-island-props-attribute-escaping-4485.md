### Island props doubled on the wire because they travelled in an HTML attribute

- **What happened:** Every server-rendered island carried its props in a `data-props` attribute. On the Assistant page with 100 chats in the sidebar, 79 KB of props JSON reached the browser as 163 KB of attribute text, a third of the 509 KB document (#4485).
- **Root cause:** Solid escapes attribute values, so each `"` in the Seroval JSON became the six bytes `&quot;`, and `&` became `&amp;`. JSON is mostly quotes, so the escaping roughly doubled the props.
- **Error class:** A transport encoding that is valid but inflates the payload: data placed in a context whose escaping rules do not fit it (JSON in an attribute, binary as text, text escaped twice).
- **Guard:** The transform writes props into a comment, the wrapper's first child (`<!--ssr-props:…-->`), and escapes only `<` and `>`, so the text can hold no comment end. A comment, unlike a JSON script, leaves `:empty`, `:first-child` and `+` as they are, which the transparent island CSS of `@k2b/ui` v2 depends on. `packages/ssr/test/unit/transform.test.ts` limits the emitted wrapper to 1.1 times Seroval's JSON for a list fixture full of quotes and reads props that try to end the comment with an HTML tokenizer. `packages/ssr/test/engine/island-props.engine.test.ts` mounts such props in a real browser, requires the same data and no injected element, and checks that a wrapper holding only its props comment still matches `:empty`.
