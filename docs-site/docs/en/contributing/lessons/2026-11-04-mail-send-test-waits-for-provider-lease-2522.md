### A direct send in a test met the draft worker's provider lease

- **What happened:** The Mail test "every settled send records one feed event…" failed in about one of four full runs of `sent-projection.integration.test.ts`. Its first send threw `REMOTE_RESOURCE_BUSY` before it reached SMTP, so no feed event existed yet.
- **Root cause:** The test sent its reply right after creating the draft. The suite's draft projection worker was still exporting that draft under the same provider lease. The outbox job resubmits a send that finds the lease busy, but the test called `executeOutboxSubmission` directly and got the error. The failing send never started, so it wrote no event. While checking whether the product can break "one event per settled send", a separate gap turned up: a send that settled twice with the same outcome, such as an unclear send whose last check gave up, reported that outcome twice. `finishOutbox` now records a `message.sent` event only when the outcome changes.
- **Error class:** A test calls a lease-guarded provider step directly while background workers in the same process can hold the lease, and treats routine contention as a failure.
- **Guard:** The suite's `send` helper waits through `whenProviderFree`, which now treats `REMOTE_RESOURCE_BUSY` like `SYNC_BUSY`, so each send waits its turn as the outbox job does. Holding the lease for 500 ms before the send fails the test without the guard and passes with it. The operator reconciliation test asserts the feed outcomes `unknown`, then `sent`.
