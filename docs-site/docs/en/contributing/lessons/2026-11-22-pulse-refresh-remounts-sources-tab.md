### A 5-second refresh re-created the Pulse sources tab and every table row

- **What happened:** On an open Pulse base, each 5-second refresh of the sources removed and re-inserted the whole tab (`section.pulse-tab`). WebKit then reset Main's scroll position to the top, and in Chromium and WebKit a focused source row lost focus to the page body.
- **Root cause:** Two causes. First, the function that returns the sources tab read `pageState()`, and with it `sources()`, in its own body instead of inside the props. Each new sources array re-ran the enclosing expression and created a new `<SourcesTab>`. Second, `DataTable` keyed its rows by object identity, so a refresh that brought new objects with the same `getRowId` still re-created every row.
- **Error class:** Focus lost on refresh (A11Y-16): reactive state read eagerly where a component is created, or a list keyed by object instead of by its stable id, re-creates focused and scrolled elements on every refresh.
- **Guard:** `packages/pulse/src/frontend/PulseWorkspace.browser.test.ts`, test "a 5-second refresh keeps the sources tab, its scroll position and the focused row", scrolls Main, focuses a source row, lets one refresh with new values run, and checks the same tab element, the same focused row and the same scroll position. Without the Pulse fix it fails in Chromium (new tab and row) and in WebKit (scroll 300 → 0); without the `DataTable` fix it fails in Chromium (scroll and row). `packages/ui/test/data-table-row-identity.behavior.test.tsx` pins that a `DataTable` row with the same id keeps its element, its focus and its open details.
