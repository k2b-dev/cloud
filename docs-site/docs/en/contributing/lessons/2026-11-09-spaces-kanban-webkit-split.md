### The Spaces Kanban WebKit suite ran its 73 cases under one budget

- **What happened:** `kanban-board.browser.test.ts` ran the whole Kanban suite in one child process with one 180 s budget. On `main`, WebKit runs took 94–172 s, and a local run on a busy machine ran out at 180 s without naming a case ([#3026](https://github.com/k2b-dev/cloud/issues/3026)).
- **Root cause:** Every new Kanban case went into the same child process, so the suite grew toward its budget unnoticed. The wrapper read the child's output only after the child exited. A run that ran out of budget therefore ended with Bun's timeout and no output at all.
- **Error class:** A browser test group whose cases are hidden from the runner grows until one file exceeds its budget, the same class as the Mail shell suite ([#1966](https://github.com/k2b-dev/cloud/issues/1966)).
- **Guard:** The suite stays one file, so the `settle-reads` and `test-clock` checks still see its helpers. Five test files each run one part of it (`describePart`) in a child process of their own, each with the unchanged 180 s budget. In WebKit, the parts took 25–47 s each. The shared wrapper collects the child's output while it runs. It stops the child 15 s before Bun's timeout, prints the output, and names the last case that finished. Bun lists passing cases in CI and in a terminal, not in an agent session. The five files carry estimated weights in `scripts/test-weights.json` until the next measurement. No repository-wide check, for the reason the Mail lesson gives.
