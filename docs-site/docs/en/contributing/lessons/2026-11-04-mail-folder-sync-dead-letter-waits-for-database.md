### Folder syncs dead-lettered without a log line during a database outage

- **What happened:** During the infrastructure outage on 01.11. at 22:44 UTC, 428 `mail:sync-folder` jobs went to the dead letter queue with `max attempts exhausted`. Mail wrote no "Mail folder sync exhausted retries" line for them and marked no folder as degraded.
- **Root cause:** `onSyncFolderJobError` awaited the degraded mark in Postgres before it logged. `markFolderDegraded` already catches a write that the database rejects, so a refused write did not make the hook throw. A write that waits for an unavailable database, however, held back both the log line and the `dead_letter` decision. Suspected: the hooks waited past the job's three-minute ack wait. JetStream then delivered the job again, and `@k2b/sync` dead-letters a delivery past `maxAttempts` as `max attempts exhausted` without calling the hook. A hook that throws ends the same way. The outage logs do not show which of the two happened for each job.
- **Error class:** A failure hook depends on the failing resource, so the outage it should report also prevents its report and its decision.
- **Guard:** The hook now logs first and then awaits the degraded mark behind a `.catch`, so neither a refused nor a waiting write keeps the line from being written or makes the hook throw. `provider-lease-fairness.integration.test.ts` holds the folder row in an open transaction, so the mark waits as it does in an outage. On the last attempt, the log line with the error code must appear while the mark still waits. Once the row is free, the hook answers `dead_letter` and the folder is marked. A mark that the database rejects also ends in `dead_letter`. A mark that waits longer than the ack wait still delays the decision, as before; the log line no longer waits for it. The dead-letter policy of folder syncs is unchanged.
