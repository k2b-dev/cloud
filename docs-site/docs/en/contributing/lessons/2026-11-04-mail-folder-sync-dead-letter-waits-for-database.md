### Folder syncs dead-lettered without a log line during a database outage

- **What happened:** During the infrastructure outage on 01.11. at 22:44 UTC, 428 `mail:sync-folder` jobs went to the dead letter queue with `max attempts exhausted`. Mail wrote no "Mail folder sync exhausted retries" line for them and marked no folder as degraded.
- **Root cause:** `onSyncFolderJobError` awaited the degraded mark in Postgres before it logged and returned its decision. `markFolderDegraded` already catches a write that the database rejects, so a refused write did not make the hook throw. A write that waits for an unavailable database, however, held back both the log line and the `dead_letter` decision. Suspected: the hooks waited past the job's three-minute ack wait. JetStream then delivered the job again, and `@k2b/sync` dead-letters a delivery past `maxAttempts` as `max attempts exhausted` without calling the hook. A hook that throws ends the same way. The outage logs do not show which of the two happened for each job.
- **Error class:** A failure hook depends on the failing resource, so the outage it should report also prevents its report and its decision.
- **Guard:** The hook now logs first, starts the degraded mark without waiting for it, and catches its rejection. `provider-lease-fairness.integration.test.ts` holds the folder row in an open transaction, so the mark waits as it does in an outage. On the last attempt, the hook must answer `dead_letter` and log the error code while the mark still waits; the folder is marked once the row is free. The existing test of a folder that gives up waits for the mark instead of reading it right after the hook. The dead-letter policy of folder syncs is unchanged.
