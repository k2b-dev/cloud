### Assertions inside a navigation callback hid their failure details

- **What happened:** The module-evaluation navigation test reported two console errors instead of one in CI (#3228), while document navigation was called exactly once. Its historical module fixture only threw; it did not log. The second error's arguments were absent from the CI output.
- **Root cause:** Suspected: a failed assertion in the `location.assign` mock became a second console error. The historical CI trigger remains unconfirmed. The test placed assertions inside that mock. Navigation catches errors thrown by that callback and logs a second diagnostic, so a failed DOM or lifecycle assertion can produce the observed count mismatch while hiding the original assertion. The escaped dev-reload listeners addressed by #3350 do not log errors themselves; a connection to this failure is unproven.
- **Error class:** A test assertion inside a caught callback can become a runtime diagnostic, obscuring the actual failure.
- **Guard:** `nav-swap.browser.test.ts` captures the mounted column, text, and lifecycle events at document navigation and asserts them after the callback returns. It checks exactly one console call, its complete navigation message, and the actual module import error. No errors are filtered out. The unchanged module fixture and full test file pass locally. This improves failure evidence; it does not claim a regression fix for the unconfirmed CI trigger, so #3228 remains open. No runtime, timeout, retry, or budget changes.
