### The island-transparent v2.css made WebKit restyle five times as long

- **What happened:** On the Notebooks graph, which draws its SVG of about 300 nodes anew in every frame, WebKit's main thread saturated: taps navigated late, a keyboard walk hung and `load` never fired. With the plain v2.css the same page drew 60 frames in 1.0 s on the test VM; with the shipped one in 5.4 s.
- **Root cause:** Two forms of the island transform (`packages/ui/scripts/v2-island-css.ts`, #4193). It wrote each rule's ways through a wrapper as one `:is()` around whole selectors, which WebKit cannot sort by the class of the subject, so it checked those rules against every new node. And it wrote `:first-child` and `:last-child` inside `:has()` as `:nth-*-child(1 of :not(:empty …))`, which makes WebKit check that `:has()` again on every change of the page. Either alone kept most of the cost; together they were all of it. The form-row spacing rule that the bisect found was only the most visible of these rules.
- **Error class:** A stylesheet transform that keeps the matching right but changes what a browser engine pays for it, measured only in Chromium.
- **Guard:** `packages/ui/src/v2/island-css-cost.browser.test.ts` draws 300 nodes in each of 40 frames beside v2 sections with islands, in Chromium and in WebKit, and fails when the shipped sheet takes more than 1.5 times as long as the plain one. The transform now writes a list of whole selectors and keeps the plain structural pseudo-classes inside `:has()`.
