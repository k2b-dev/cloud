### Contacts address map tests ran a page load, a flow and a reload inside Bun's 5 s default

- **What happened:** In WebKit, `the focused address editor preserves a picked point through reload` in `packages/contacts/src/frontend/_components/ContactAddressGeo.browser.test.ts` (#2892) hit the test timeout of exactly 5 s, twice in one day on pull requests that did not touch Contacts. Both times it stopped while the click on the Adressen section waited for the element, and the page was then closed under it.
- **Root cause:** Every test in the file opens its own page, and the file gave its tests no budget of their own. The reload case loads the page, picks a suggestion, saves, reloads and opens the section. Measured in the Playwright WebKit image on an idle machine, that took 4.4–4.7 s, and the step after the reload started at about 4.1 s. Passing CI runs took 2.8–4.5 s. No step hung: the budget ran out during the last steps. Other tests of the file also took up to 4.7 s in CI.
- **Error class:** A browser test that opens its own page runs under the runner's default test timeout, which is meant for one step, not for a page setup and a flow. It is the same class as the Chat message edit tests (2026-10-29).
- **Guard:** The file gives its tests 30 s with `setDefaultTimeout`, and each page keeps 5 s for one step. A check is still not useful: 1,002 tests in 180 browser files that open pages have no budget of their own, and many of them reuse one page, so a rule cannot tell a single step from a flow. The testing guide asks each test that opens its own page for a budget.
