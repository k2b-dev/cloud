### The pending line of an answered question was read before it was announced

- **What happened:** The case "sending moves nothing above the card, and running to done moves the line by 0 px" in `action-question.browser.test.ts` read an empty status where it expected "wird gesendet …". It failed in job `unit (2)` of runs 39309690586, 39315605053, and 39325083603, in the panel 22rem and the 1440 variant, and blocked #1567, #1569, and #1564 with the release PR behind it ([#1572](https://github.com/k2b-dev/cloud/issues/1572)).
- **Root cause:** `ChatOutcome` in `@k2b/ui` empties its `role="status"` region and fills it in a 40 ms timer, so that the same words spoken again are a change too. The test read the region once after `settled()`, which waits for fonts, animations, and two frames, not for timers. Under load, the read came before the timer. The fixture already held its answer until the test released it, so the suspected answer timer was not the cause. With the page's 40 ms timers delayed to 500 ms, the old case failed in all three variants in 4 of 4 runs. The product was correct.
- **Error class:** Live region read before its announce timer filled it.
- **Guard:** While the fixture holds the answer, the test waits with `waitForFunction` until the status says "wird gesendet …", then releases the answer. With the 40 ms timers delayed to 500 ms, it passes in every variant. The convention is in [Wait for conditions, not time](/en/docs/contributing/testing#wait-for-conditions-not-time). No check, because a source rule cannot tell which live regions fill after a timer.
