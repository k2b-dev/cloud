### A test restored TZ as the string "undefined", and a later Venue test read the wrong day

- **What happened:** `Venue shift detail and schedule > links every calendar date to the venue's own day east of UTC` failed on main's merge queue at 23:42 UTC on 31 October, when Berlin already had 1 November (#2300). The calendar's Today link pointed to 31 October, the test expected 1 November. The file passed alone; it failed only in the package's `bun test` run.
- **Root cause:** `packages/venue/src/time-format.test.ts` sets `process.env.TZ` and restored it with `process.env.TZ = originalTimeZone`. With `TZ` unset, as in CI, that stores the string `"undefined"`, an invalid zone, for every later file in the same process. The Venue render test also compared against `new Date()`, so it depended on the time of the run: it could only fail in the hour when the Berlin day and the UTC day differ.
- **Error class:** A test leaks global state (an environment variable restored as `"undefined"`), and a test reads the real clock, so a failure appears only at certain times and only in a shared process.
- **Guard:** The restore deletes `TZ` when it was unset. The Venue test freezes the clock with `setSystemTime` at 23:42 UTC on 31 October, so it checks the venue's day at exactly the moment when Berlin and UTC differ, on any day. With the clock frozen but the old restore, the package run failed every time; with both changes it passes (218/218). A check rule for bare `process.env.X = saved` restores found 31 more sites and is tracked separately.
