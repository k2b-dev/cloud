### A choice popover widened itself inside its own ResizeObserver delivery

- **What happened:** The WebKit browser test for adding the first manager to an app failed most runs with `ResizeObserver loop completed with undelivered notifications.` on the Code integration branch. The share dialog there names a longer notice for a search that finds nobody.
- **Root cause:** Two parts in `packages/ui/src/inputs/choice.ts`. The loader reported "not loading" while a search waited out its debounce, so the Combobox showed the "nobody found" notice before any request ran, and the long notice widened the popover. The popover keeps its widest width while open, but it applied that floor only on its next placement: when the short result made it narrower, the ResizeObserver callback wrote the floor back as `min-width`. The popover resized during the observer's own delivery, which WebKit reports as an error.
- **Error class:** A ResizeObserver callback that writes a size back to the element it observes; a loading state that starts after a debounce instead of when the search is scheduled.
- **Guard:** `packages/ui/src/inputs/combobox-resize.browser.test.ts` types into a Combobox in Chromium and WebKit: during the debounce it shows loading rows at the field's width, and shorter results keep the popover's width without a page error. `choice-inputs.render.test.tsx` checks that the loader is loading from the scheduled search until it answers or is cancelled.
