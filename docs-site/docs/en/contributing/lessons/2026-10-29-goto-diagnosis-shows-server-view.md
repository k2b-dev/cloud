### A Chat page request stayed open, and the diagnosis could not say which side lost it

- **What happened:** In WebKit, `Search in the chat list > a chat hit is its ordinary row; nothing found says so; Escape brings the list back` in `packages/chat/src/frontend/ChatSearch.browser.test.ts` failed on an unrelated pull request (#2107): the `goto` to the Chat harness waited 5 s with no response and no document, and `GET /app/chat` was still open (#2109).
- **Root cause:** Not yet known. The harness answers `/app/chat` synchronously, no browser process crashed, and the runner had the 8 MiB receive buffer from #1367. The navigation diagnosis only showed the browser's view, so it could not tell whether the request reached the test server. The pattern appeared once in about 80 failed runs.
- **Error class:** A failure report shows only one side of a request, so a lost request cannot be placed.
- **Guard:** `recordTestServer()` in `packages/ui/test/browser.ts` lets a test server record what it received and answered. For every request that is still open, a timed-out navigation now prints the server's view: never received, received but never answered, or answered with a status. The Chat harness records its requests. `packages/ui/test/browser.browser.test.ts` checks both cases in Chromium and WebKit. The next occurrence names the side that lost the request, and #2109 stays open until then.
