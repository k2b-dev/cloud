### Any change inside a page restyled the whole page through the shell's selectors

- **What happened:** Inserting one element deep in an app page restyled about 8,200 elements on a shell test page with 4,200 elements. Removing the rules from #2420 brought this to 70–390 elements, but the count still grew with the page: with 1,500 content rows it was 3,000 to 3,400 elements per change, in every app, on every typed key, streamed message or opened menu.
- **Root cause:** In Chromium, a `:not()` or a state pseudo-class in any `:has()` argument makes every DOM change check `:has()`. The check restyles each element that matches a part after a `:has()` that is not on the styled element, such as `.c` in `.a:has(.b) .c`. Shared rules asked the document, `body` or the workspace about deep descendants (`html:has(.k2b-mobile-shell) .k2b-button`, `.k2b-ui:has(.k2b-page-title…)`) or named parts that occur many times (`.k2b-button__label`, `.k2b-button`). Measurements show this behavior; we did not read Blink's source.
- **Error class:** Style that depends on a scan of a large subtree instead of on state that its owner knows. It is invisible on small test pages and grows with the page.
- **Guard:** `shell-restyle.browser.test.ts` changes a node deep in five shell layouts at desktop and phone width. It fails if the restyled count grows when the page doubles, or if it exceeds the shell's fixed share. The `css-has-scope` rule refuses a `:has()` that reaches any depth on the document, `body`, the shell or a workspace, and a part after a non-subject `:has()` that a page holds many times.
