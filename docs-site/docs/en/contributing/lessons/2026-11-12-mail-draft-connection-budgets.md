### Collaborative draft buffers need a process budget

- **What happened:** Mail bounded edit packets per socket but did not cap live connections. Awareness delivery waited for SQL on a plain NATS live subscription, while each document peer created its own broker follower. At 200 drafts, cancellation and cleanup hung with the application SQL pool reserved.
- **Root cause:** Per-connection limits did not bound aggregate work or broker buffering. Topic handles were created per connection, so their hubs could not share a follower. A separate saturation witness confirmed that cancellation also queued on that same reserved pool, while reservations waited for cancellation before releasing their slots. A second isolated witness confirmed that calling Bun SQL `cancel()` before awaiting a lazy query can leave it unsettled forever; an already-aborted signal must reject before starting that query. The corrected 200-draft load still fails with a stream error, but its cleanup drains. That capacity failure remains unresolved.
- **Error class:** Locally bounded queues with unbounded aggregate admission; cancellation waiting on its own exhausted dependency.
- **Guard:** `draft-document-socket-sql.integration.test.ts` saturates the SQL pool and requires cancellation to return every reservation, including an abort before the first lazy query. `draft-document-budget.test.ts` and `draft-document-socket.integration.test.ts` check process and peer admission, byte budgets, slow-reader cutoff, idle expiry, abrupt disconnects and cleanup. `packages/mail/scripts/draft-document-load.ts` measures real socket propagation, retained storage and RSS under an external resource budget.
