### Verify the transport and interaction contracts after a picker migration

- **What happened:** Destination previews failed in PostgreSQL, Files rejected an unclassified service method, and access-editor browser tests still expected desktop options on phones.
- **Root cause:** The batch audience reader bound serialized JSON directly as `jsonb`, so Bun encoded it as a JSON string. The new Files reader was missing from the effects table. Browser tests assumed Select's option roles and full-width trigger; RichSelect uses buttons in a phone sheet and a content-sized trigger. A phone choice could open a confirmation before focus returned to the field, so cancelling lost focus. An open-state test also waited for global animation settling while sheet closure restored trigger focus.
- **Error class:** Contract drift across database bindings, service effects, and responsive controls.
- **Guard:** `summarizeAccessAudience` in `packages/cloud/src/server/services/access.test.ts` and the Spaces wormhole transfer integration test exercise the real database binding. `activity-classification.test.ts` requires every Files service method to declare its effects. `AppAccessEditor.browser.test.ts` exercises both responsive selection surfaces and retains the approved field height and permission-column width. The phone commit tests verify trigger focus inside the callback both on a page and in a parent dialog, and the access-editor cancellation test verifies focus after confirmation. The RichSelect consequence-picker browser test waits for the reported open state and the corresponding surface visibility.
