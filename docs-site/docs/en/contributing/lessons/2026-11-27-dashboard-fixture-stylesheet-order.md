### Dashboard widget states overflowed in production because the test linked the stylesheets the other way round

- **What happened:** On a real page, a medium dashboard tile in the loading, timeout or error state, and the quote widget with its provider down, scrolled by 18 to 38 px and cut off its message. This happened at every width in German and English. The fit test meant to catch this passed.
- **Root cause:** `.dashboard-page .dashboard-widget-placeholder { padding: 0 0.75rem }` and `@k2b/ui`'s `.k2b-ui .k2b-placeholder { padding: 1.5rem 0.75rem }` have the same specificity. A Cloud page links the app's `app.css` before the shared `global.css` (`define-app.ts`), so the shared rule won and added 24 px of block padding. The test linked `styles.css` before `app.css`, the reverse order, so the dashboard rule won there.
- **Error class:** A fixture loads stylesheets in a different order than the production page, so rules of equal specificity resolve differently, and the test checks a cascade no user sees.
- **Guard:** The dashboard fit test (`dashboard-home.browser.test.ts`, "every built-in widget fits its frame") links the sheets in production order. With the fix, every element of the fit board computes the same styles in both orders at 1440 px. `scripts/fixtures/page-assets.ts` (#4403) takes the app's sheet first; the eight other fixtures in the reverse order are #4420.
