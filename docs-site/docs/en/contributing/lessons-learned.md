# Lessons learned

A bug that is fixed once can come back in another place. To stop that, every
fix names the error class of its bug, then adds or names the guard that
catches that class next time. A guard is a repository check under
`scripts/checks/`, a test that fails on the bug, or a named convention that
reviews apply. Checks and tests fail on their own. A convention works only
while reviews apply it, and a rule that nothing checks decays. The table marks
each guard as a check, a test, or a convention, so a class that has only a
convention still needs a check or a test.

## Error classes

| Class | What goes wrong | Current guard |
| --- | --- | --- |
| A CI check imports an unbuilt workspace package | A fresh job installs dependencies but the check runner loads rules that import the UI package before its exported files exist. | Test: `scripts/nightly-ui-build.test.ts` requires every Nightly job that runs repository checks to build UI first. |
| Input consumed before deterministic validation | The client clears a message that the server rejects on every retry, leaving the person unable to correct the text. | Tests: Chat `ChatWorkspace.behavior.test.tsx` and `ChatWorkspace.browser.test.ts` reject oversized text before queuing, preserve the draft, and send it after correction. The composer and API share `MessageBodySchema`. |
| Mixed timestamp precision drops measured requests | A recorder compares fractional browser starts with an integer end timestamp, discarding a required request in the final millisecond and reporting zero transferred bytes. | Test: Mail `page-change-network.browser.test.ts` fixes the fractional boundary while a real script remains pending, then requires its actual transfer; the cached-script guard still requires zero encoded transfer. Convention: compare measurement boundaries and request starts at the same precision. |
| Positional input-union compatibility | A manifest check rejects preserved input variants after additions or reordering, or accepts a `oneOf` change that makes old inputs match multiple variants. | Tests: Cloud `_internal/capabilities.test.ts` covers nested additive unions, required disjoint tags, removed or narrowed branches, overlaps, optional tags, and unchanged result-union restrictions. |
| An app adds an unnecessary administration group | A single administration entry declares `adminNav`, separating it from the shared app administration list. | Test: Pulse `frontend/admin/navigation.render.test.ts` checks the German and English SSR sidebar and mobile snapshot, active link, default data-store tab, and unchanged admin-only route access. Convention: use `adminHref` for one app administration entry. |
| Shared interaction behavior implemented for only some consumers | Resize handles differ in cue, keyboard behavior, or reset depending on the region. | Tests: UI `resize-cue.browser.test.ts` covers every workspace edge and standalone separator; separator, workspace controller, and Cloud panel behavior tests cover reset callbacks and saved-size removal. |
| Unread fetch error bodies | A reader returns its fallback after response headers but leaves the unused body open, keeping a browser request pending. | Tests: Cloud `app-badges.behavior.test.tsx` covers cleanup rejection, absent bodies, aborts and disposal; `app-badges.browser.test.ts` checks real finite and streaming error responses, terminal network events and server disconnects through `watchAppBadges`. |
| Incomplete stored-state fixtures | A direct SQL fixture omits one of the fields that domain writers persist together, creating a state that normal writes cannot produce. | Test: `yjs-snapshot-projections.integration.test.ts` checks the persisted cursor and its matching sequence before publishing in both initialization cases, then asserts that the real snapshot save succeeds ([#1651](https://github.com/k2b-dev/cloud/pull/1651)). |
| A clear keeps the measured usage | Clearing a base empties its data but keeps the usage that the storage threshold reads, so ingest refuses the empty base until the next usage scan. | Test: Pulse `service/base-lifecycle.integration.test.ts` clears a base over its threshold and checks that usage and the threshold crossing are reset. |
| A late domain refusal becomes an infrastructure failure | An ingest reservation commits, then T2 returns a service conflict that a catch-all replaces with 503. | Test: Pulse `service/ingest-controls.integration.test.ts` raises a T2 service refusal after a keyed T1 and expects its own 409. |
| A merge changes the winning observation | A deduplicated view orders by observation time, but physical replacement orders only by acceptance; later merges silently discard the correct state. | Test: Pulse `service/state-transitions.integration.test.ts` checks state timestamp priority before and after a forced merge and schema replay. |
| A predecessor lookup ignores retention boundaries | A lagging hour selects its own rollup, or shorter rollup retention hides a predecessor whose raw samples remain. | Tests: Pulse `service/metric-rollups.integration.test.ts` checks a late correction before the raw cutoff and a sparse counter after its old rollup is removed. |
| A profile row limit breaks a truncation probe | A read profile with `result_overflow_mode=throw` rejects `LIMIT n+1` when its own limit is n; row estimates cannot establish truncation reliably. | Test: Pulse `store/sql-run.integration.test.ts` checks 10,000 and 10,001+ source rows; execution requests 10,000 and marks exactly 10,000 as limit reached, with possible additional rows. |
| A rollback loses evidence of an external write | A sample or state survives in ClickHouse while a later insert rolls back its Postgres watermark or state decisions, so corrections miss successors or retries lose history. | Test: Pulse `service/metric-rollups.integration.test.ts` fails after the sample insert, then checks that an earlier counter dirties and repairs the successor hour. Pulse `service/retention.integration.test.ts` applies a tombstone, fails the SQL delete, and checks that committed retirement intent lets the next write revive the series. Pulse's partition-drop fault test checks that seals and their watermark remain committed after raw data is removed, including after a retention extension. Pulse `service/ingest-identity.integration.test.ts` checks committed state plans before inserts and replays interrupted history after a newer batch succeeds; an unkeyed resend after a failed insert records the change once, at its first acceptance time. |
| A registry deletion leaves a visible mirror | Retention frees the Postgres series budget while the ClickHouse series remains visible. | Test: Pulse `service/retention.integration.test.ts` checks failed tombstone inserts, immediate view removal with merges stopped, and reuse of the freed budget. |
| A removed route strands a CLI command | A route disappears while a CLI command still sends requests to it. | Tests: Pulse `cli.test.ts` matches the command's actual request against the API router; `api/source-ingest.test.ts` checks write access, public IDs, body bytes, idempotency and retry headers. |
| A reset leaves an earlier reservation valid | One reset path changes a timestamp while another empties the data without changing it, so an earlier ingest writes into the reset store. | Test: Pulse `service/ingest-identity.integration.test.ts` runs clear and recreate between T1 and T2, expects 409 and empty views, and then accepts a new write. Convention: every base reset increments its durable generation before removing data or registries. |
| A schema rebuild keeps stale mirror acknowledgements | A recreated database is empty while Postgres still says its sources and series are mirrored. | Test: Pulse `service/source-mirror.integration.test.ts` rebuilds missing and empty databases through provision and clear, retries source mirrors, and re-mirrors series on the next write. |
| A seal outruns a pending retry | Retention seals an hour that a still valid idempotency reservation may replay, so the retry of a partly stored batch is refused for good. | Test: Pulse `service/retention.integration.test.ts` fails a keyed batch after its first insert, lets the lease expire, runs retention and completes the retry before the hour is sealed. |
| Raw principal id rendered as a name | A missing name or an unresolved grant response replaces a person’s name and avatar initials with a UUID. | Check: `principal-id-labels` rejects principal ID fallbacks, label functions returning IDs, IDs in ternary branches and template spans in text positions, and IDs as JSX text. Tests: `principal-label.test.ts`, `PermissionEditor.behavior.test.tsx`, `StudioPermissions.behavior.test.tsx`, and the missing-principal suite in `access.test.ts`. |
| Rendered Markdown dropped by the email sanitizer | marked emits an element, here `hr` from `---`, that the email allowlist lacks, so the divider disappears from sent mail while help and editor show it. | Test: Mail `compose-renderer.test.ts` pins the exact set of elements email drops from a render of every Markdown construct; Cloud `email-html.test.ts` and `email-frame.test.ts` keep `hr`. |
| Immutable asset URL names different builds | A start stamp changes stylesheet URLs after every restart and can name different Core files during a rolling deploy ([#1544](https://github.com/k2b-dev/cloud/issues/1544)). | Tests: Cloud `define-app.stylesheet-versions.test.ts` checks real restarts, shared Core URLs, changed and missing app files, and development stamps; `static-assets.test.ts` checks version matching, source hashes, missing files, in-place changes, and 304 cache policy. |
| Concurrency bounded by count, not by memory | Background worker counts allow several large items to hold more memory together than the process can afford. | Tests: Mail `processing-memory-budget.test.ts` checks weighted FIFO admission, oversized work, cancellation and release; `processing-memory.integration.test.ts` checks peak RSS and correctness under the guard workload ([#1549](https://github.com/k2b-dev/cloud/issues/1549)). |
| Optional app absence shown as an error | The consumer could not tell an app that is not installed from a failed call. | Mail: one registry-aware resolver, explicit `absent` contact state, and conversation-context render and behavior tests. |
| Decode work bounded only by file size | One record consumes the whole file's decode budget on every lookup, or a probe keeps many large records at once. | Tests: Cloud `geoip.test.ts` checks the 32 KiB record boundary, isolated failure and refusal of a valid record with a huge array; GeoIP `index.test.ts` checks upload refusal and that the probe keeps no record between addresses. |
| Navigation truncation drift | Component or app CSS reintroduces an ellipsis, lets labels in a scrolling strip shrink to fragments, or a mask clips the navigation control's focus ring. | Tests: UI `truncate-fade-contract.test.ts` rejects ellipsis and line clamps across shipped navigation families; `truncate-fade.render.test.tsx` checks inner label classes; `sidebar-row-labels.browser.test.ts` checks overflow, resizing, RTL, focus, and stable heights; `view-tabs.browser.test.ts` checks at 390 px and in a narrow head that no view tab is narrower than its content and that the current and focused tabs lie in view outside the edge fade ([#1550](https://github.com/k2b-dev/cloud/issues/1550)). |
| Browser cookie store read races a document write | WebKit stores a `document.cookie` write asynchronously, so a test reading `context.cookies()` immediately can see the previous value ([#1496](https://github.com/k2b-dev/cloud/issues/1496)). | Check: `cookie-store` requires `storedCookie(page, name)` from `packages/ui/test/browser.ts` to wait until the store agrees with the document, or a leading `// cookie-store: <reason>` for a deliberate read such as an HttpOnly cookie. |
| Navigation-refused load reported as a page error | While the main frame waits for the next document, WebKit refuses a load that the old page starts, such as a stream that reconnects after the navigation cancelled it. It logs `Fetch API cannot load <url> due to access control checks.` even for a handled same-origin request, Playwright reports that as a `pageerror`, and a test that expects no page errors fails at random ([#1579](https://github.com/k2b-dev/cloud/pull/1579), [playwright#43120](https://github.com/microsoft/playwright/issues/43120)). | Test: `packages/ui/test/browser.browser.test.ts` checks in Chromium and WebKit that `pageErrors(page)` ignores only that report during a test's navigation, and still reports an unhandled rejection, a refusal during a navigation the page starts, and access-control failures for another origin. Convention: [collect page errors with `pageErrors(page)`](/en/docs/contributing/testing#test-in-chromium-and-webkit). No check yet, because about 40 older suites register their own `pageerror` listener. |
| Remote content in mail | A sent message or its preview loads an image from a remote address, so opening it tells the sender's server who read it and when. Mail images come only from stored bytes, sent as an inline `cid:` part and previewed as a `data:` URL. | Test: Mail `outbound-mime.test.ts` (the logo is a `multipart/related` inline part whose `Content-ID` matches the HTML, no `http(s)` image source) and `compose-renderer.test.ts` (Markdown images, `<img>`, and CSS `url()` or `image-set()` stay rejected). |
| Derived theme text color without a contrast guarantee | A fixed CSS mix derives text from an app accent, so a light accent such as yellow falls below 4.5:1 on the surfaces it sits on. | Test: `packages/cloud/src/ssr/app-color.test.ts` checks the computed ink of every declared app accent and edge accents against each listed background in both themes, and pins the background constant and the `:root` defaults to `tokens.css` and `@k2b/ui` ([#1205](https://github.com/k2b-dev/cloud/issues/1205)). No check covers other text colors derived in CSS yet. |
| Raw app accent as text or focus ring | An app paints `var(--app-accent)` itself as text or a focus outline. A light accent such as yellow falls below 4.5:1, and the focus ring changes per app instead of staying the platform focus. | Check: `bun scripts/check.ts selection-tokens` (kind `accent-raw`) rejects `var(--app-accent)` in `color`, `outline`, `outline-color` and `border-color` declarations and in `text-`, `outline-`, `ring-` and `border-` utilities in app source; backgrounds such as the Mail unread dot stay allowed. Tests: `scripts/checks/selection-tokens.test.ts`. |
| A pinned color base drifts from the surface an element uses | A constant pins the background a derived color is mixed over. A shell change moves the element to another token, so the fill no longer matches the contract while value-only drift tests stay green. | Test: `packages/cloud/src/ssr/app-color.test.ts` reads the `.k2b-ui .k2b-app-workspace__sidebar` background declaration from @k2b/ui and checks that the navigation fill's base equals what it resolves to in both themes. |
| App colors lost at a dialog portal | App colors live only on the page canvas, so dialogs mounted under the body inherit platform defaults. | Tests: `packages/cloud/src/ssr/dialog-app-colors.browser.test.ts` checks portalled settings, selected rows, stable category geometry, and nested accent scopes in both themes and viewport sizes; `packages/cloud/src/ssr/Layout.render.test.tsx` checks the real shell's validated accent scope ([#1458](https://github.com/k2b-dev/cloud/issues/1458)). |
| Platform selection color on an app row | A selected navigation or object row keeps the platform blue (`--ui-selected`, `--k2b-selected`, `bg-blue-50`) or mixes the raw `--app-accent`, so it ignores the app color and its AA-checked ink. | Check: `bun scripts/check.ts selection-tokens` rejects new platform fills and raw accent mixes in app source; control and status uses need an allowlist reason, and stale entries fail. Tests: the AccountHub, file chooser and resource picker browser tests compare picked or current rows with the app hooks; the Mail list, Files list, Grids object list, Contacts list and Notebooks sidebar browser tests compare open, checked and picked rows with the app hooks. The Grids overview, admin and public document page, Notebooks overview, Tools catalog and tool header, and Mail compose intent render tests, plus the Grids overview icon and Tools tool icon browser tests, keep app icons on `k2b-icon-tile` with app ink and platform focus. |
| Selection drawn as a filled primary button | A chosen view, range, segment or on/off filter is drawn as a filled primary Button through a variant swap, so two accent fills stand side by side and the selection ignores the app’s selection tint. | Check: `bun scripts/check.ts selection-tokens`, kind `selected-button`. Tests: Accounts request and group-detail page and toolbar render tests, `@k2b/ui` FilterToggle render/behavior tests, Core AiUsageExplorer behavior test, Gateway Ops RangeTabs and observability page render tests, and the Gateway Ops `RangeTabs.browser.test.ts` in Chromium and WebKit. |
| A mutation’s refresh re-creates a rendered entity’s element | Refetched objects replace retained elements, losing focus and hover and leaving box reads detached. | Tests: Spaces kanban and detail claim tests use `keptThrough()` from `packages/ui/test/browser.ts` to check element identity and height; the held-card test distinguishes a retained card from one leaving its column ([#1391](https://github.com/k2b-dev/cloud/issues/1391)). |
| Reconciliation fails after a write | A lost response leaves a create outcome unknown, or a failed canonical reread leaves a pin pending forever. Retrying a create can duplicate it. | Pulse browser tests keep the source draft, block another create, expose the canonical source list, and release pin pending state with a visible recovery action. |
| A restored entity shows twice, or a test reads it page-wide | Undo or a refresh puts an item back while the leaving copy still shows, or a page-wide role locator matches two elements. `expect(promise).resolves` hides why the read failed. | Test: the Spaces tray Undo and refresh tests use `mostAtOnce()` from `packages/ui/test/browser.ts`. Convention: scope reads to the entity's row and await reads directly ([#1450](https://github.com/k2b-dev/cloud/issues/1450)). Mail `scripts/browser-smoke.ts` keeps a mailbox name equal to the conversation subject, selects the conversation row by ID, and checks its navigation URL. |
| Nested event loop in a Playwright test | Bun's `expect(promise).resolves`/`.rejects` runs a nested event loop. Playwright's in-process channel then delivers messages out of order, protocol validation fails, the connection closes, pending calls reject, and stale JsonPipe messages throw `Cannot find object to "message": jsonPipe@…` into the next test. | Check: `browser-test-promises` rejects `.resolves`/`.rejects` in files that drive Playwright ([#1502](https://github.com/k2b-dev/cloud/issues/1502)). |
| Nested reservations starve the SQL pool | A transaction waits for a service or settings lookup that needs another pooled connection. | Tests: Pulse's two-connection scrape and source-key regressions, one-connection notification regression, and orphan-deletion settings boundary unit test. |
| Grant issued after account sign-out | A password check, approved grant or consumed login approval creates credentials after its account epoch changes, or an older user token still resolves. | Tests: OAuth code/device/rotation and migration cases, Core reservation and epoch checks, Cloud token epoch checks, Cloud Login/session completion cases, and Cloud `me-password-sign-out.integration.test.ts` for password sign-in overlapping a password change and expired-password/reset-link issuance overlapping a sign-out. | Lasting access created from an unconfirmed sign-in | A reusable credential creates another personal credential, or a sign-in ages before the write commits. | Tests: Cloud personal-key and passkey transaction checks, OAuth code/device confirmation cases, Core evidence and terminal grant-binding checks. Convention: check the browser session inside the write transaction and require recorded confirmation before activating a refresh family. |

| Relative navigation URLs in offline documents | A PDF renderer resolves web paths against its local HTML file. | Test: Notebooks `note-pdf.integration.test.ts` checks actual PDF URI annotations against the public origin and rejects `file://` ([#1365](https://github.com/k2b-dev/cloud/issues/1365)). |
| Session URL in a server-side export | A server-side renderer gets a URL that only a signed-in browser can load, so the content silently disappears. | Tests: Notebooks `book-renderer.test.ts` checks that print HTML for every documented image form has no app, API, or `attach://` URL; `note-pdf-images.integration.test.ts` checks embedded images with `pdfimages` and zero requests with `gotenberg-trap.ts` ([#1280](https://github.com/k2b-dev/cloud/issues/1280)). |
| Unreported export loss | A PDF replaces content with a label, source, or error notice without telling the caller. | Tests: Notebooks `book-renderer.test.ts` checks typed omissions against rendered diagnostics and content order; `pdf-omissions.test.ts` checks the header budget; API and gateway tests check delivery. |
| Release notes parsed as HTML | HTML-like placeholders swallow release sections, so release-please skips a component or mixes its notes with another release. | Check: `release-body` CI job (`scripts/check-release-pr-body.ts`) parses release PR bodies with the pinned release-please parser; the `check` job reads live PR text on PR and merge queue runs and refuses markup in titles, body commit headers, BREAKING CHANGE paragraphs, and nested-commit blocks; a self-test checks that lint against the pinned commit parser ([#1298](https://github.com/k2b-dev/cloud/issues/1298)). |
| Release commit that release-please cannot parse | A commit on `main` whose title is not a Conventional Commit, such as the `Merge commit from fork` that a security advisory merge writes, drops out of the release without a warning: its fixes and breaking change miss the changelog and the version bump. | Convention: [an advisory merge gets an override pull request](/en/docs/contributing/release-process#release-a-fix-merged-from-a-security-advisory) that lists the advisory's entries in `BEGIN_COMMIT_OVERRIDE` and changes a file in every component the advisory changed. No check finds such commits on `main` yet. |
| Squash message that wraps into another commit | The squash merge writes the pull request body wrapped at about 72 columns. Text that parses in the body can break once wrapped: a line that now starts with a word directly followed by an opening parenthesis, such as `` `color-mix( ``, can make release-please drop the whole commit, and a line that now starts with a word and a colon reads as a second commit. This dropped #1559 and #1564 from the release-please changelog before 0.47.0. | Convention: before a release merges, parse every squash commit since the last release with the pinned `parseConventionalCommits` ([release process](/en/docs/contributing/release-process#branch-and-merge)) and restore a dropped `feat` or `fix` with an override pull request. No check parses the wrapped message yet ([#1592](https://github.com/k2b-dev/cloud/issues/1592)). |
| Advisory pull request compared with a stale fork `main` | The pull request in a security advisory fork compares its branch with the fork's own `main`, which GitHub does not keep current. It can show no conflict while its head conflicts with `main`, so the maintainer cannot merge it on the advisory page. | Convention: [before the maintainer merges](/en/docs/contributing/release-process#release-a-fix-merged-from-a-security-advisory), fast-forward the fork's `main` to `main`, merge `main` into the fork branch, and trial-merge its head onto `main` with `git merge-tree`. No check covers the fork yet. |
| Silent truncation by a clamped page size | A caller asks for the whole collection with a page size above the helper's maximum and exports only the first page. | Check: `page-size` rejects oversized `pagination.perPage` literals. Tests: Contacts export pagination, cancellation, stream failure, serializer bytes, and the 1,001-contact integration case ([#1241](https://github.com/k2b-dev/cloud/issues/1241)). |
| SQL parameters infer the wrong type | A date parameter in a SELECT, CASE, or arithmetic expression becomes text or an interval before assignment. | Tests: Pulse ingest identity, scrape, rollup, and store maintenance integration suites execute the SQL against PostgreSQL. |
| SQLSTATE read from the wrong driver field | A schema retry checks only `code`, while Bun exposes PostgreSQL's SQLSTATE in `errno` with a generic `code`. | Tests: notification `catalog.test.ts` covers all supported schema states in both fields, retry completion, and propagation of initial non-schema errors. |
| Claim and assignment diverge | A person works on a task while assignment-based lists still show it as unassigned, or a stale assignee replacement removes an active worker. | Tests: `packages/spaces/src/service/claim-assignment.integration.test.ts` checks transactional user claims, guarded assignee replacements, forced releases, completion, and idempotent backfill ([#1269](https://github.com/k2b-dev/cloud/issues/1269)). |
| Paint outside a scrollport | An outline or outset shadow, such as a status ring, reaches past its element and a scrolling ancestor flush with it cuts it off. | Test: `packages/ui/src/layout/detail-panel-sections.browser.test.ts` checks that an avatar ring flush with the detail body paints inside the scrollport and keeps the avatar size. |
| A tenant boundary that holds only on paper | A read user can reach another tenant, hidden fields, system metadata or external table functions, or can widen its resource limits. | Test: Pulse `store/read-access.integration.test.ts` runs the HTTP attack matrix against both bases and every read profile, checks exact grants, and proves its sensitive-column guard with a temporarily widened grant. |
| A token leaks through structured CLI output | The command redacts text but prints the raw API response in JSON. | Test: Pulse `cli.test.ts` checks text, JSON and JSONL output, exclusive file creation and mode 0600. |
| Unbounded storage growth | Durable payloads have no size bound or retention. | Tests: workflow event integration cases cover byte limits, payload retention, dedupe, and resumable runs; workflow observability integration cases cover expired payloads; Mail integration cases cover oversized messages ([#1183](https://github.com/k2b-dev/cloud/issues/1183)) and body-less message events ([#1313](https://github.com/k2b-dev/cloud/issues/1313)); `chat-tasks.integration.test.ts` covers 90-day scheduled task run retention in bounded batches. |

| Reused keys collide across reservation lifetimes | Deterministic row IDs include an expiring key but omit the reservation identity, so a later batch replaces an earlier event. | Tests: Pulse `service/ingest-bulk.test.ts` checks new IDs across acceptance times and stable IDs on retry; `service/ingest-identity.integration.test.ts` expires and reuses a key for the same event kind and timestamp and keeps both events. |

| Write that bypasses the domain history | An app writes to external storage through a path that never opened its history entry, such as a derived client or a new method. | Check: `filegate-facade` prevents SDK access outside the Files facade. | Outcome inferred from appearance | Recovery marks an operation done because the target looks right, although another writer could have created it. | Test: `activity.integration.test.ts` recovery cases keep lost folder responses unclear and accept only a late real result as done. |
| Motion choice ignored | JavaScript or a separate document animates despite the person's reduced-motion choice. | Tests: `MailConversationReader.behavior.test.tsx` checks the choice at jump time; `MailMessageBody.browser.test.ts` checks initial and live propagation into the sandboxed message and rejects frame-originated motion messages ([#1230](https://github.com/k2b-dev/cloud/issues/1230)). |

## Lessons

### Pulse retention confirmation and lowered policy limits

- **What happened:** A retention confirmation could delete data under settings the person had never previewed; lowering the raw retention maximum also blocked unrelated settings edits.
- **Error class:** Confirmation without a state precondition; policy validation rejects unchanged stored values.
- **Guard:** Pulse's `store/retention.integration.test.ts` checks all three stale retention periods without writes, matching confirmation, unchanged over-maximum retention, and refusal of changed values above the maximum; API and frontend error-mapping unit tests preserve the preview baseline and visible conflict error.

### Replicas that booted together failed their setup (#1562)

- **What happened:** Two FAQ replicas migrating a fresh schema together repeatedly left one failing with `23505` on `pg_namespace_nspname_index`. Existing schemas could fail on duplicate constraints or triggers, or concurrent catalog updates ([#1562](https://github.com/k2b-dev/cloud/issues/1562)).
- **Root cause:** `CREATE IF NOT EXISTS` and drop-then-create DDL were safe to repeat, but lifecycle setup ran on every replica without serialization.
- **Error class:** Rerun-safe treated as concurrent-safe startup DDL.
- **Guard:** The platform holds a renewed NATS lease per application during setup. `setup-lock.test.ts` covers waiting, renewal, release, and lease loss. `setup-lock.integration.test.ts` boots two real processes through ten cold and ten warm rounds, checks non-overlapping setup intervals, and kills a holder to verify recovery after lease expiry. The scale harness starts all replicas together, Core first, and requires `RestartCount` 0 after readiness.

### Stopping one replica removed routes for the survivors (#1561)

- **What happened:** A clean replica stop removed the shared app and capability entries. The gateway dropped the app’s routes until a survivor’s next refresh ([#1561](https://github.com/k2b-dev/cloud/issues/1561)).
- **Root cause:** Every replica wrote the same keys and deleted them unconditionally on stop. No membership check protected the shared entries from a stop racing a new replica’s start.
- **Error class:** Shared resource removed by one of several owners.
- **Guard:** The replica-membership cases in `heartbeat.test.ts` cover clean stops, surge races, TTL expiry, late writes, registry failures, a survivor replacing the entry of a departed newer replica, and a newer replica taking back an entry that an older one repaired. A stale stop snapshot cannot remove shared entries unless at least half the membership lease remains. `heartbeat.integration.test.ts` checks real Sync watches. The nightly scale-acceptance `chat-replica-stop` scenario checks gateway requests across a graceful stop and a surge rollout, and requires the container to be stopped with exit code 0 and no OOM kill before removal.

### Large Mail messages exhausted container memory (#1549)

- **What happened:** Mail 0.43.0 was OOMKilled at a 1 GiB container limit while hydrating messages up to about 34 MiB and extracting attachments ([#1549](https://github.com/k2b-dev/cloud/issues/1549)). In the production image, the `incident` load case of `packages/mail/scripts/memory-load.ts` reached about 1,040 MiB RSS before the fix and about 790 MiB after it.
- **Root cause:** Four hydration workers could parse large messages together. HTML sanitizing added 30–38 times the HTML size, and CSV extraction built all Markdown before truncating it. Blob chunk copies and read-ahead added allocation churn.
- **Error class:** Concurrency bounded by count, not by memory.
- **Guard:** `processing-memory-budget.test.ts` checks one shared weighted FIFO budget, oversized work running alone, cancellation and release after failure. `processing-memory.integration.test.ts` runs the memory guard workload and checks peak RSS, the budget high-water and complete messages and attachments. Blob streaming keeps one pending chunk and bounds read-ahead. `message-hydration-admission.integration.test.ts` checks that a download error emitted before admission cancels the waiter, destroys the source and releases the claim with the original retryable error; an emitted error alone does not end an ImapFlow download stream.

### Changing chats kept the destination composer read-only

- **What happened:** Moving to another chat while an app-opening draft save waited kept the destination composer read-only until the save finished or Escape was pressed.
- **Root cause:** Every draft-key change was treated as the opener's own move to a newly created chat.
- **Error class:** User navigation mistaken for an async action's own navigation.
- **Guard:** `chat-slash.behavior.test.ts` checks immediate cancellation on unannounced draft changes, ignores late results, and consumes `follow()` for one move. `composer-app-commands.behavior.test.tsx` checks that navigating during a save frees the destination composer before the save finishes and still allows the opener to create a plain chat.

### A Command whose code could not load counted as opened

- **What happened:** When the code for opening an app Command could not load, the Assistant removed the slash and kept the draft saved without it, although nothing opened.
- **Root cause:** `openCommand` resolved the same way after showing its reload notice as after opening.
- **Error class:** Nothing-opened outcome read as success.
- **Guard:** `openCommand` resolves `false` when nothing opened, tested in `commands.behavior.test.tsx`; `composer-app-commands.behavior.test.tsx` checks that the slash and the live draft stay.

### A throttled Mail provider looked like a missing message

- **What happened:** Empty reads could fail commands as missing, confirm deletes or moves, mark bodies missing, or retire local messages ([#1244](https://github.com/k2b-dev/cloud/issues/1244)).
- **Root cause:** ImapFlow ends FETCH without rows when its throttle retries run out. SEARCH returns false on command failure. Mail treated these answers as absence.
- **Error class:** Absence from an empty provider answer.
- **Guard:** `%s confirms an empty FETCH answer before it reports a message as gone` in `packages/mail/src/service/connectors/imap-smtp.test.ts` drives real ImapFlow against a throttling server for every affected read. New reads that infer absence use the same confirmation helper. A source the provider lists but never delivers still uses the missing-source budget (`downloadSourceBatch skips a source the provider lists but never delivers and streams the rest`).

### Server-rendered charts need an island for inspection

- **What happened:** Grids Custom App charts displayed their plots but offered no hover, keyboard, or tap inspection on published pages. The builder preview also lost category names in tooltips.
- **Root cause:** The page rendered the chart outside an island. The plot deliberately suppressed category labels inside SVG, so default tooltips could not recover those names or the block's value format.
- **Error class:** Inert server-rendered interaction.
- **Guard:** Grids `chart-tooltip.test.ts` checks category and aggregation labels and value formatting. `page.render.test.tsx` checks the chart island, SVG parity, and display-only serialized props for signed-in and anonymous pages. `chart-tooltips.browser.test.ts` covers real island mounting, hover, keyboard, tap, and server/browser layout parity at desktop and phone widths.

### release-please skipped the Cloud release 0.44.0

- **What happened:** Merging release PR #1248 created the npm releases but no `cloud-v0.44.0`; images and CLI assets needed a manual recovery ([#1298](https://github.com/k2b-dev/cloud/issues/1298)).
- **Root cause:** A BREAKING CHANGE footer contained `<dir>`-style text. release-please parses the release PR body as HTML, so the unclosed tag swallowed the Cloud section.
- **Error class:** Release notes parsed as HTML.
- **Guard:** The `release-body` CI job parses each release PR body with the pinned release-please parser, on the PR and in the merge queue. Its self-test fails on the #1248 body as merged. The `check` job refuses such markup in PR titles and release text in PR bodies. [Release process](/en/docs/contributing/release-process#recover-a-release-that-release-please-skipped) records the recovery.

### Contacts exports stopped at 1,000 contacts

- **What happened:** CSV and vCard book exports silently omitted contacts after the first 1,000 ([#1241](https://github.com/k2b-dev/cloud/issues/1241)).
- **Root cause:** The export requested `perPage: 100_000`, which `paginate()` silently clamped to 1,000.
- **Error class:** Silent truncation by a clamped page size.
- **Guard:** `page-size` rejects oversized pagination literals. Contacts unit tests cover keyset cursors, cancellation, serializer bytes, and failed streams; `export.integration.test.ts` checks both downloads with 1,001 contacts.

### A claimed Spaces task still appeared unassigned

- **What happened:** A person could claim a task without becoming an assignee, so assignment filters missed work already in progress ([#1269](https://github.com/k2b-dev/cloud/issues/1269)).
- **Root cause:** Claim writes and assignee replacements treated working state and responsibility as independent data.
- **Error class:** Claim and assignment diverge.
- **Guard:** `claim-assignment.integration.test.ts` checks that user claims assign once, holder removal is guarded before any write, forced release removes the previous holder, and startup backfill repairs old user claims. The existing item row lock serializes claim writes and assignee replacements.

### Concurrent upload commits rejected each other

- **What happened:** Two tabs uploading small files into the same storage root lost commits to retryable busy errors ([#1165](https://github.com/k2b-dev/cloud/issues/1165)).
- **Root cause:** Private commits shared a broker root lease configured for a single acquisition attempt, so even brief contention rejected publication immediately.
- **Error class:** Ordering and concurrency.
- **Guard:** `filegate-lifecycle.integration.test.ts` pairs forty real uploads at their commit boundary. `files.integration.test.ts` checks publication after a short lock, busy after the five-second wait, one shared wait budget for a multi-entry move, immediate root-lock attempts without a wait or after its budget expires, and immediate capability-upload rejection without consuming its body. Publications and trash mutations opt into a wait per request; listings and administrative lifecycle operations retain a single attempt.

### Access refetches drop keyboard focus and close member lists

- **What happened:** Saving an access change dropped focus to the page body and closed expanded group members in several applications ([#1283](https://github.com/k2b-dev/cloud/issues/1283)).
- **Root cause:** Consumers keyed the whole editor by refetched data or hid it during refresh. Contacts also replaced its pickers with read-only badges while reloading. Keeping the editors mounted exposed two refresh races: mutation success could overwrite a caller's newer permission list after loading cleared, and key creation could insert a credential already supplied by the caller.
- **Error class:** List re-keyed on refresh drops focus.
- **Guard:** Check: `access-editor-mounts` rejects keyed, `refreshing()`-gated, or resource `loading`-gated `Show` and `Match` ancestors. Tests: `PermissionEditor.browser.test.ts` preserves the focused chip after a keyboard change and consumer refetch at phone and desktop widths; behavior tests cover merging by id, stale refetches after a save, deferred updates, caller copies, and Contacts and Venue reloads. `PermissionEditor.behavior.test.tsx` checks that caller refreshes win after update and revoke callbacks finish; `ResourceApiKeys.behavior.test.tsx` checks that creation replaces a refetched credential in place without duplicating it.

### Accepted iPhone photos failed in a closed settings panel

- **What happened:** Tools accepted HEIC files, but browsers without native HEIC support showed no image or visible failure ([#1284](https://github.com/k2b-dev/cloud/issues/1284)).
- **Root cause:** Image loading depended on native browser decoding. Load errors appeared only in a detail panel that was closed for an empty batch or on phones.

With an 8 MiB default receive buffer, 4,200 navigations had no stall, and the kernel pruned no queue. The whole graph test file failed in 11 of 40 CI runs with the defaults, three times with a Back that WebKit ended as an internal error, and passed all 40 runs with the setting.
- **Error class:** Loopback receive queue collapse.
- **Guard:** `.github/actions/install` sets the default receive buffer to 8 MiB for every socket opened after it, and the `ci-install` check makes every CI and nightly job use that action. [Testing](/en/docs/contributing/testing#when-a-page-never-fires-load) explains how to read the socket evidence and how to apply the setting locally.

### The OAuth card was read before its styles arrived

### A cancelled touch was counted as ink

- **What happened:** `SignatureInput in chromium > a cancelled touch is not a stroke` found one ink path instead of none in 2 of 20 local runs of the `@k2b/ui` browser files under load ([#1495](https://github.com/k2b-dev/cloud/issues/1495)). CI had not shown it.
- **Root cause:** The test's `swipe()` sent the touch over `Input.dispatchTouchEvent` and returned when the last call returned. That call returns once the browser has passed the touch on, not once the page has handled it: with the main thread blocked for 300 ms at the last move, the `touchCancel` call returned after 15 ms and `pointercancel` reached the page after the block. The count then could read the ink of the stroke still in progress. `SignatureInput` itself drops that ink in the same `pointercancel` handler and ignores later events of the cancelled pointer. A blocked main thread alone does not make the old count read 1, because Chromium dispatches the queued touch before the later read; the read gets ahead only while the touch is still on its way inside the renderer, which a loaded machine allows.
- **Error class:** State sampled before it settled.
- **Guard:** `swipe()` installs a one-shot capture listener for the last touch before it sends one, waits until the page has recorded that touch, then one frame. The cancel case first waits for the ink of the finger that is still down, then for the handled cancel, and expects no ink and no change. A case blocks the main thread for 500 ms at the last pointer event, for a lifted and a cancelled touch, and checks that `swipe()` returns only after that; the old `swipe()` returned after 205 to 220 ms.

### Busy-machine timeouts in the touch-target and PageTitle tests

- **What happened:** In WebKit on a busy machine, the touch-target case "keep the message field's edge above the chat composer footer, …" and the PageTitle case "an app's own title takes the same height at every depth, …" hit bun's 5000 ms test timeout, PageTitle in 3 of 5 runs ([#1497](https://github.com/k2b-dev/cloud/issues/1497)). The values that the tests check were never wrong.
- **Root cause:** The fixed work of the tests, not the product. Each step was measured with `performance.now()` in five parallel runs at a load of 44 to 53 on 24 cores. The DetailPanel case tapped every pixel of every control twice: 129,440 `elementFromPoint` calls, 3.5 s median in Chromium and 2.6 s in WebKit. The composer case opened five pages (1.6 s in WebKit), loaded eight documents that each parsed the inlined 857 KB `dist/styles.css` again (1.4 s), and scanned for 1.4 s. In 10 such runs per engine, the composer case timed out 6 times in WebKit and the DetailPanel case 4 times in Chromium. Styling and laying out the composer itself took less than 10 ms per state.

## Add a lesson

A fix pull request answers "How do we prevent this next time?" and adds its
entry here in four lines: what happened, root cause, error class, and guard.
When neither the code on `main` nor a test confirms the root cause, start it
with "Suspected:"; the fix pull request replaces it with the confirmed cause.
When the guard does not exist yet, write "Pending in #n" with the issue that
tracks it, or "None, because …". A pull request that adds a guard for a class
updates that class's row in the table.
